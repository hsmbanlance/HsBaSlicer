## 引言
本文件面向 HsBaSlicer 的核心模块，聚焦以下目标：
- 全面说明 base、utils、fileoperator、meshmodel、cadmodel、pointcloud、support、paths 等模块的职责、接口与使用方式。

- 结合源码实证，避免臆造 API；所有引用均标注具体文件与行号。

HsBaSlicer 是一个面向增材制造切片的高性能 C++ 框架，模块化、跨平台，适用于研发与生产级流水线。其核心库 LibHsBaSlicer 暴露预处理、切片、支撑、填充、路径生成五大能力；DllHsBaSlicer 提供 C ABI 的运行时流水线接口，便于多语言集成。

## 项目结构
仓库按职责划分多个子模块：
- base：基础类型与通用工具（单例、线程池、协程、委托、反射等）。
- utils：应用配置、序列化、Lua 绑定辅助。
- fileoperator：ZIP/SQLite/属性树/Lua 适配器/参数持久化。
- meshmodel：网格模型（CGAL/IGL/拓扑重建）。

- support：FDM/SLA 支撑生成与悬垂检测。
- paths：层路径、点路径、图像路径、机器人路径输出。
- LibHsBaSlicer：C++ 全流程切片封装。
- DllHsBaSlicer：C ABI 流水线导出层。

### base 模块：基础类型与工具
- 单例 Singleton<T>：线程安全的单例模板，通过 std::call_once 保证唯一实例构造，对外暴露 GetInstance()。
- 线程池 ThreadPool：管理 worker 线程队列，支持 submit、WaitAll、PendingTasks、ActiveTasks；析构时优雅停止并 join。
- 协程 coroutine：定义 IExecutor/NoopExecutor/AsyncExecutor 执行器抽象，Task<T, Executor> 提供 then/catching/finally 链式回调，CustomAllocatorTask 支持自定义分配器；Generator<T> 提供 yield_value 迭代器语义。

## 性能与优化建议
- 线程池与协程
  - 使用 ThreadPool 并行提交独立任务，避免阻塞主线程；合理设置线程数（默认 hardware_concurrency）。
  - 对 IO 密集或 CPU 密集任务分别选择合适的执行器（AsyncExecutor 或 ThreadPoolExecutor）。
- 内存与对象生命周期
  - 使用 Singleton 管理全局资源，避免重复构造开销。
  - 对频繁分配的对象考虑 CustomAllocatorTask 或对象池（base/object_pool.hpp）以减少碎片。
- 网格与 CAD
  - 优先使用 FullTopoModel 的 SliceFast 以利用已重建拓扑；仅在需要开放轮廓时使用 UnSafeSlice。
  - CAD 布尔运算与抽壳可能昂贵，建议在预处理阶段合并/简化模型。
- 点云
  - 先 Downsample 再 ComputeNormals/GenerateMesh，减少体素网格规模。
  - KNN/RadiusSearch 前可先 Voxelize 提升查询效率。
- 参数存储
  - 批量 SaveBatch 使用事务，减少锁竞争与磁盘同步次数。
  - 开启 SetCryptoKey 会引入加解密开销，按需启用。

## 故障排除指南
- 线程池提交失败
  - 现象：向已停止的 ThreadPool 提交任务抛出运行时错误。
  - 排查：确认未提前销毁线程池；检查 num_threads > 0。
  - 参考：[base/thread_pool.hpp:37-46](file://base/thread_pool.hpp#L37-L46)、[base/thread_pool.hpp:77-89](file://base/thread_pool.hpp#L77-L89)
- 协程结果未就绪
  - 现象：Task.get_result() 等待完成；若未正确 await 或调度，可能导致死等。
  - 排查：确保使用 then/catching/finally 或显式 get_result；检查 IExecutor 是否正确执行回调。
  - 参考：[base/coroutine.hpp:277-316](file://base/coroutine.hpp#L277-L316)
- 参数存储错误
  - 现象：Save/Load 抛出异常，last_error 非空。
  - 排查：检查 EnsureSchema 是否执行；校验 cfg 字段类型与约束；确认 crypto_key 一致。
  - 参考：[fileoperator/param_store.hpp:45-102](file://fileoperator/param_store.hpp#L45-L102)
- 网格拓扑不完整
  - 现象：SliceFast 抛错或切片结果异常。
  - 排查：先调用 CheckTopo 与 EulerCharacteristic 检查；必要时回退到 Safe/Unsafe Slice。

## 结论
HsBaSlicer 的核心模块围绕“模型—切片—支撑—路径”的主干流程组织，base/utils/fileoperator 提供基础设施与数据持久化，meshmodel/cadmodel/pointcloud 提供几何与 CAD 能力，support/paths 完成支撑与路径输出。LibHsBaSlicer 将这些能力整合为统一的 C++ 接口，DllHsBaSlicer 进一步暴露 C ABI 以便跨语言集成。通过合理的线程池/协程使用、拓扑检查、点云降采样与参数存储事务化，可在保证正确性的同时获得良好的性能表现。
