## 项目构建配置概述

本项目采用CMake作为构建系统，通过`CMakeLists.txt`和`CMakePresets.json`文件实现灵活的构建配置。项目支持多平台构建，包括Windows、Linux、macOS和Android，并通过条件编译和预设配置实现不同构建目标的定制化。

## 核心CMake配置解析

### C++标准与UTF-8支持

项目明确要求CMake最低版本为3.21，并在CMake版本大于3.12时设置C++标准为20：

```cmake
if(CMAKE_VERSION VERSION_GREATER 3.12)
  set(CMAKE_CXX_STANDARD 20)
endif()
```

对于MSVC编译器，项目强制启用UTF-8编码支持，确保源代码文件以UTF-8格式编译：

```cmake
if(MSVC)
  add_compile_options("$<$<C_COMPILER_ID:MSVC>:/utf-8>")
  add_compile_options("$<$<CXX_COMPILER_ID:MSVC>:/utf-8>")
endif()
```

这一配置确保了项目在Windows平台上正确处理中文等Unicode字符。

### 调试后缀配置

项目设置了调试版本的后缀为'd'，这对于Windows平台上的库链接具有重要意义：

```cmake
set(CMAKE_DEBUG_POSTFIX "d")
```

此命名约定允许在同一系统中同时存在调试版本和发布版本的库文件，避免链接冲突。例如，`LibHsBaSlicer.lib`对应发布版本，而`LibHsBaSlicerd.lib`对应调试版本。

## 编译选项与条件编译宏

### 功能模块条件编译

项目通过一系列条件编译宏控制不同功能模块的启用：

#### CAD内核支持

当目标平台不是Android、iOS或SWITCH时，项目启用OpenCASCADE作为CAD内核：

```cmake
if(NOT ANDROID AND NOT IOS AND NOT SWITCH)
  find_package(OpenCASCADE CONFIG REQUIRED)
  add_compile_definitions(USE_OCCT)
  add_compile_definitions(USE_CAD_KERNEL)
endif()
```

`USE_OCCT`宏的定义直接影响代码编译，例如在`pch_headers.hpp`中：

```cpp
#ifdef USE_OCCT
#include "cadmodel/OcctModel.hpp"
#endif // USE_OCCT
```

#### 网络数据库支持

根据平台不同，项目有条件地启用MySQL和PostgreSQL支持：

```cmake
if(NOT ANDROID AND NOT IOS AND NOT SWITCH)
	find_package(Sqlpp11 CONFIG REQUIRED COMPONENTS SQLite3 MySQL PostgreSQL)
	add_compile_definitions(USE_MYSQL)
	add_compile_definitions(USE_PGSQL)
else()
	find_package(Sqlpp11 CONFIG REQUIRED COMPONENTS SQLite3)
endif()
```

#### 调试模式优化

在调试构建配置中，项目禁用布尔运算以避免调试模式下的性能问题：

```cmake
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
  add_compile_definitions(DISABLE_BOOLEAN_OPERATIONS)
  message("Disable boolean operations in Debug configuration for CGAL and IGL.")
  message("Boolean operations may be slow and cause high memory usage in Debug mode.")
endif()
```

此宏在测试代码中被进一步细化为`DISABLE_BOOLEAN_OPERATIONS_TESTS`，用于控制测试用例的执行。

## 构建预设与缓存变量

### 预设配置结构

`CMakePresets.json`文件定义了多平台的构建预设，采用继承机制实现配置复用：

```json
{
  "name": "windows-base",
  "hidden": true,
  "generator": "Ninja",
  "binaryDir": "${sourceDir}/out/build/${presetName}",
  "installDir": "${sourceDir}/out/install/${presetName}",
  "toolchainFile": "$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake",
  "cacheVariables": {
    "CMAKE_C_COMPILER": "cl.exe",
    "CMAKE_CXX_COMPILER": "cl.exe"
  },
  "condition": {
    "type": "equals",
    "lhs": "${hostSystemName}",
    "rhs": "Windows"
  }
}
```

### 构建类型预设

基于基础预设，项目定义了不同架构和构建类型的预设：

```json
{
  "name": "x64-debug",
  "displayName": "x64 Debug",
  "inherits": "windows-base",
  "architecture": {
    "value": "x64",
    "strategy": "external"
  },
  "cacheVariables": {
    "CMAKE_BUILD_TYPE": "Debug"
  }
}
```

`x64-release`预设继承自`x64-debug`，仅修改构建类型为Release，体现了配置的层次化设计。

### 跨平台预设

项目为不同平台提供了专门的构建预设：

- **Linux**: `linux-debug`和`linux-release`
- **macOS**: `macos-debug`和`macos-release`
- **Android**: `android-release`（arm64架构）

Android预设特别配置了NDK相关参数：

```json
"cacheVariables": {
  "CMAKE_BUILD_TYPE": "Release",
  "VCPKG_TARGET_TRIPLET": "arm64-android",
  "VCPKG_CHAINLOAD_TOOLCHAIN_FILE": "$env{ANDROID_NDK_HOME}/build/cmake/android.toolchain.cmake",
  "ANDROID_NDK": "$env{ANDROID_NDK_HOME}",
  "ANDROID_ABI": "arm64-v8a",
  "ANDROID_PLATFORM": "android-28",
  "CMAKE_SYSTEM_NAME": "Android"
}
```

## 库构建策略

### 静态库与动态库

项目采用混合的库构建策略，不同组件根据需求选择静态或动态链接：

#### 静态库

`LibHsBaSlicer`被定义为静态库，包含核心切片功能：

```cmake
add_library(LibHsBaSlicer STATIC 
  pch_headers.hpp
  Slice/mesh_slice.hpp
  Slice/mesh_slice.cpp
)
```

#### 动态库

`DllHsBaSlicer`被定义为共享库（动态链接库），用于跨语言调用：

```cmake
add_library(DllHsBaSlicer SHARED 
  dllexport.h
  ../cpp.hint
  initialize.h
  initialize.cpp
)

target_compile_definitions(DllHsBaSlicer PRIVATE HSBA_SLICER_EXPORTS)
```

`HSBA_SLICER_EXPORTS`宏用于控制符号的导出，在Windows上对应`__declspec(dllexport)`。

### 主应用程序构建

主应用程序`HsBaSlicer`的构建策略根据平台而异：

```cmake
if(ANDROID)
  add_library(HsBaSlicer SHARED "HsBaSlicer.cpp" "HsBaSlicer.h")
else()
  add_executable (HsBaSlicer "HsBaSlicer.cpp" "HsBaSlicer.h")
endif()
```

在Android平台上构建为共享库以便打包进APK，在其他平台构建为可执行文件。

## 测试模块配置

### 测试开关控制

项目通过`HSBA_SLICER_USE_TESTS`选项控制测试模块的构建：

```cmake
option(HSBA_SLICER_USE_TESTS "use tests" ON)

if(ANDROID OR IOS)
  set(HSBA_SLICER_USE_TESTS OFF)
  message("Disable tests on Android or IOS.")
endif()

if(HSBA_SLICER_USE_TESTS)
	add_subdirectory("tests")
endif()
```

此配置确保移动平台（Android和iOS）上不构建测试代码，优化构建时间和部署包大小。

### 条件性测试

测试代码的构建也受到功能可用性的影响：

```cmake
if(TARGET HsBaSlicerCADModel)
  add_executable(occt_model_test Models/occt_model_test.cpp)
  # ...
endif()
```

只有当`HsBaSlicerCADModel`目标存在时（即OpenCASCADE可用），才会构建OCCT相关的测试。

## 压缩功能配置

### bit7z压缩后端

项目通过`HSBA_USE_BIT7Z`选项控制bit7z压缩后端的启用：

```cmake
option(HSBA_USE_BIT7Z "use bit7z" ON)

if (HSBA_USE_BIT7Z AND NOT ANDROID)
	add_compile_definitions(USE_BIT7Z)
	find_package(unofficial-bit7z CONFIG REQUIRED)
endif()
```

`USE_BIT7Z`宏在代码中用于条件编译压缩相关功能：

```cpp
#ifdef USE_BIT7Z
#include <bit7z/bitfileextractor.hpp>
#include <bit7z/bitfilecompressor.hpp>
#include <bit7z/bitexception.hpp>
#endif // USE_BIT7Z
```

### 压缩库路径配置

项目定义了不同平台下7-Zip库的默认路径：

```cpp
#ifdef USE_BIT7Z
#if _WIN32
    const std::string HSBA_7Z_DLL = "C:/Program Files/7-Zip/7z.dll";
#elif __APPLE__
    const std::string HSBA_7Z_DLL = "/usr/local/lib/7z.dylib";
#elif __linux__
    const std::string HSBA_7Z_DLL = "/usr/lib/7z.so";
#else
    const std::string HSBA_7Z_DLL = "";
#endif
#endif // USE_BIT7Z
```

这些路径在`bit7z_zipper.cpp`和`bit7z_unzipper.cpp`中被用于初始化bit7z库。
