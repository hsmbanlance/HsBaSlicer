## 引言
本文档面向 HsBaSlicer 的流水线架构，系统性解释其在多种 3D 打印技术栈中的设计模式、执行流程、参数传递机制和错误处理策略。随着代码库的重构，现在引入了新的 LibHsBaSlicer/Pipeline 层，为 FDM、SLA、SLS、SLM、LOM、TDP、WAAM 以及 Lua 自定义流水线提供独立的内核实现，同时保持 C ABI 接口的向后兼容性。文档覆盖所有技术栈的核心数据类型、配置结构、执行流程和扩展点，为初学者提供友好概览，同时为高级用户提供足够的技术深度。

## 项目结构
HsBaSlicer 的流水线相关代码现在采用三层架构：
- **C ABI 接口层**：pipelinetypes/pipeline_types.h 定义统一的 C 语言接口
- **Pipeline 内核层**：LibHsBaSlicer/Pipeline/* 提供各技术栈的具体实现
- **底层能力层**：LibHsBaSlicer/* 提供切片、填充、支撑、路径生成等基础功能

## 核心概念
- **分层架构**：C ABI 接口层提供稳定的外部接口，Pipeline 内核层封装具体工艺逻辑，底层能力层提供通用功能。
- **统一内核**：每个技术栈都有对应的 RunXxx() 函数作为单一事实来源，确保 C ABI 和 C++20 模块行为一致。
- **配置驱动**：通过 pipeline_types.h 中的 POD 结构体传入工艺参数，支持默认初始化和字段验证。
- **进度回调**：所有流水线支持 Hooks.progress 回调，便于 UI 更新与任务监控。
- **协作取消**：通过 Hooks.cancel_flag 实现可中断的流水线执行。
- **几何捕获**：可选的 GeometryCapture 功能用于模型预览和调试。

## 核心组件

### 内核类型系统
- **GeometryCapture**：每层几何数据捕获结构，包含轮廓、填充、支撑和路径信息。
- **Hooks**：内核回调接口，包含进度回调和取消标志。
- **统一输出结构**：每种技术栈都有对应的 Output 结构体，包含 success、total_layers、error、elapsed_seconds 等标准字段。

### 配置系统
- **枚举类型**：填充模式、支撑图案、固件目标、材料、光源、保护气体等工艺参数。
- **配置结构体**：FDM、SLA、SLS、SLM、LOM、TDP、WAAM、Lua 自定义流水线的完整配置。
- **默认初始化器**：HsBaXxxConfigDefault() 为各配置提供合理的默认值。

### 结果系统
- **成功标志**：success 字段表示流水线是否成功完成。
- **层数统计**：total_layers 记录处理的层数。
- **错误信息**：error_message 或 error 字段提供详细的错误描述。
- **性能指标**：elapsed_seconds 记录执行时间。
- **取消状态**：cancelled 字段指示是否因用户取消而终止。

## 详细组件分析

### FDM 流水线内核
FDM 流水线实现了完整的熔融沉积建模工艺流程，包括预处理、切片、支撑生成、填充计算和 G-code 路径生成。

**关键特性**：
- 支持螺旋模式（花瓶模式）：跳过支撑与填充，外层轮廓合并为连续上升路径
- 填充支持内置算法与 Lua 自定义脚本
- 顶层/底层使用实心填充保证表面质量
- 路径生成根据打印机配置与固件目标输出 G-code

### SLS/SLM 流水线内核
SLS（选择性激光烧结）和 SLM（选择性激光熔化）流水线共享相似的架构，都基于切片和 Lua 脚本导出。

## 性能与并发特性
- **并行切片**：所有流水线在切片阶段使用 ParallelForLayers 对层进行并行处理，提升吞吐。
- **串行限制**：Lua 自定义填充/支撑因解释器状态不可跨线程共享，采用串行执行以保证正确性。
- **协作取消**：通过 cancel_flag 实现可中断的流水线执行，避免长时间阻塞。
- **几何捕获优化**：仅在需要时捕获层几何数据，减少内存占用。

## 错误处理与资源管理
- **异常捕获**：所有流水线协程使用 try/catch 捕获 RuntimeError 和 CancelledError。
- **早期失败**：模型加载失败、层数为无效值、缺少必需 Lua 导出脚本等情况会提前返回错误。
- **内存释放**：C ABI 返回的字符串内存由调用方负责释放，对应 Free*PipelineResult 函数。
- **进度回调**：ReportProgress 在关键阶段上报百分比与阶段描述。

## 调用示例与最佳实践
- **同步调用**：构造配置后调用 HsBaRun*Pipeline(config, callback, user_data)，然后调用 HsBaFree*PipelineResult(result)。
- **异步调用**：构造配置后调用 HsBaRun*PipelineAsync(...)，并提供 result_callback 接收结果。
- **进度回调**：在 progress_callback 中更新 UI 或记录日志，stage 字段描述当前阶段。
- **最佳实践**：始终检查 success 与 error_message；对于 SLS/SLM/LOM/TDP，务必提供有效的 export_lua_script。

## 故障排除指南
- **模型加载失败**：检查 model_name/model_path 是否正确，确认模型文件存在且可读取。
- **层数为无效值**：检查 layer_height/first_layer_height 是否合理，模型高度是否为正。
- **缺少 Lua 导出脚本**：对于 SLS/SLM/LOM/TDP，确保 export_lua_script 非空且路径有效。
- **导出失败**：检查输出路径权限与磁盘空间；查看 error_message 中的 Lua 错误信息。
- **内存泄漏**：确保调用 HsBaFree*PipelineResult 释放结果中的字符串字段。

## 结论
HsBaSlicer 的新版流水线架构通过引入 LibHsBaSlicer/Pipeline 层，实现了更好的代码组织和可维护性。新的三层架构（C ABI 接口层、Pipeline 内核层、底层能力层）确保了向后兼容性的同时，提供了更清晰的职责分离。每个技术栈都有对应的内核实现，通过统一的 RunXxx() 接口暴露，既保持了 API 的一致性，又允许针对不同工艺进行专门优化。这种设计使得开发者可以更容易地添加新的技术栈支持，同时也为现有功能提供了更好的测试和维护基础。
