# 切片作业采用提交-轮询异步队列而非长连接流式返回

_来源：ca9d258 → ae47e03 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
切片流水线可能耗时较长，HTTP 请求线程若直接阻塞会耗尽工作线程；同时需支持进度上报与错误状态查询。

## 决策驱动
- 避免 HTTP 线程被长时间阻塞
- 允许客户端在任意时刻查询进度
- 与现有同步版 HsBaRun*Pipeline 保持一致的回调语义

## 备选方案
- **WebSocket 或 SSE 推送进度** _（已否决）_ — 优点：实时推送，减少轮询开销；缺点：增加协议复杂度；当前无实时 UI 驱动；测试与部署更复杂
- **Async 版 pipeline result_callback 直接写 HTTP 响应** _（已否决）_ — 优点：回调即完成点，代码路径短；缺点：回调线程与 HTTP 线程耦合；无法表达 queued/running 中间态；失败时难以统一错误处理
- **进程内 Job 队列 + worker 线程池 + 轮询 GET** — 优点：状态机清晰（queued→running→success/failed）；进度/阶段可持久到 Job；TTL 清理简单；缺点：客户端需轮询；大结果暂存进程内存

## 决策
POST /api/jobs/{kind} 返回 202 + {id, state:"queued"}，GET /api/jobs/{id} 轮询状态，GET /api/jobs/{id}/result 下载成功结果；Job 结构持有自管理 buffer 深拷 HsBa*PipelineResult_t，worker 线程调用同步版 HsBaRun*Pipeline 并通过 progress 回调更新 job.progress/stage。

## 影响
API 简洁、易测试；但大 G-code 文本驻留进程内存，需依赖 TTL 后台清理；队列满时返回 429；删除 running 作业拒绝 409。
