- 压缩/解压后端通过抽象接口解耦：`IZipper` 为纯虚接口，`IUnzipper` 采用 CRTP 模板基类，具体实现（miniz、bit7z）仅覆盖 `*Impl` 私有方法并通过友元声明暴露给基类。
- 可选第三方库（bit7z、MySQL、PostgreSQL、Boost.Log）一律通过 CMake 预处理器宏（`HSBA_HSBA_USE_BIT7Z`、`HSBA_USE_MYSQL`、`HSBA_USE_PGSQL`、`ANDROID/IOS/GAME_CONSOLE`）进行条件编译，头文件中用 `#ifdef` 包裹对应类或函数。
- SQL 适配器统一继承 `ISQLAdapter` 并使用 PIMPL（`class Impl; std::unique_ptr<Impl> impl_`）+ `std::shared_mutex` 实现线程安全，错误通过继承 `IOError` 的 `SQLAdapterError` 派生类抛出。
- SQL 客户端 API 通过重载 `operator|` 提供管道式 fluent 调用，对 rvalue 引用版本的 `operator|` 显式 `= delete` 以防止误用。
- PipelineConfig 类型的字段反射通过 `HSBA_PARAM_FIELD` 与 `HSBA_PARAM_DEFINE_CONFIG_TYPEINFO` 两个宏批量生成 `GetTypeInfo<T>()` 特化，新增配置结构只需追加宏调用即可注册。
- 面向 Lua 的导出函数均以 `RegisterLuaXxx(lua_State*)` 命名并按功能分组（Zipper/Bit7z/SQL/ParamStore），由 `LuaAdapter.cpp` 统一集中注册。
