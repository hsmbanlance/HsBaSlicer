模块以 CMake 静态库 `HsBaSlicerFileOperator` 形式组织，按功能划分为四个相对独立的子层：
- 压缩/解压抽象层：`IZipper.hpp` 定义纯虚接口，`zipper.cpp` 基于 miniz 实现 `Zipper`；`IUnzipper.hpp` 通过 CRTP 模板基类 `IUnzipper<Derived>` 暴露 `ReadFromFile`/`GetStream`，由 `unzipper.cpp`（miniz）和 `bit7z_unzipper.cpp`（可选 bit7z）分别实现，统一通过 `UnzipperStream`（封装内存 buffer 或临时文件）对外暴露读取流。
- SQL 适配层：`sql_adapter.hpp` 在 `HsBa::Slicer::SQL` 命名空间内定义 `ISQLAdapter` 接口及 SQLite/MySQL/PostgreSQL 三个后端，均使用 PIMPL + `shared_mutex` 保证线程安全，并提供一套 `operator|` 管道风格的 fluent API（`SQLSelect`/`SQLInsert`/`SQLDelete`/`SQLUpdate`/`SQLCreateTable`/`SQLRemoveTable`）。
- 参数反射与持久化层：`param_reflect.hpp` 通过宏 `HSBA_PARAM_FIELD` / `HSBA_PARAM_DEFINE_CONFIG_TYPEINFO` 为各 `*PipelineConfig_t` 结构生成 `Utils::TypeInfo` 注册表，驱动 `param_store.cpp` 将任意配置对象序列化为 SQL 行（`param_schema.cpp` 负责建表，`param_convert.cpp` 做类型转换），并由 `properties_doc.cpp` 导出文档。
- Lua 绑定层：`LuaAdapter.cpp/.hpp` 集中暴露 `RegisterLuaZipper`/`RegisterLuaBit7zZipper`/`RegisterLuaSQLiteAdapter`/`RegisterLuaMySQLAdapter`/`RegisterLuaPostgreSQLAdapter`/`RegisterLuaParamStore` 等入口，作为上层脚本访问上述能力的唯一通道。
- 辅助层：`RemoteExecutor.{hpp,cpp}` 提供到远端执行器的文件发送连接与轮询连接池；`rw_ptree.cpp` 提供 ptree 读写工具。
依赖方向单向向外：LuaAdapter → 压缩/解压 + SQL + ParamStore；压缩/解压与 SQL 之间无相互依赖；所有可选特性（bit7z、MySQL、PostgreSQL、Boost.Log）通过 CMake 条件编译开关控制。
