本模块按用途划分为三个并列子目录，彼此无相互依赖：
- `cmake/`：供顶层 CMakeLists.txt include 的片段库。`HsBaSlicerConfig.cmake.in` 通过 `find_dependency` 声明对外暴露的头文件依赖（Eigen3、magic_enum、Clipper2、Lua、Protobuf、OpenSSL）并导出 `HsBaSlicerTargets.cmake`；`coverage.cmake` 在 GNU/Clang 下启用 `--coverage`，用 gcovr 对 core/other 两组目录分别执行行覆盖率阈值门控（`HSBA_COVERAGE_THRESHOLD_CORE`/`OTHER`），并通过自定义 target `coverage` 串联 JSON 解析与两份 gate 报告；`HsBaWindowsUtf8.cmake` 提供 `hsba_apply_utf8_codepage(<target>)` 函数，仅在 MSVC+Windows 下把 `hsba_utf8.manifest` 以 `/MANIFESTINPUT` + `/MANIFEST:EMBED` 链接进可执行文件，使进程级 ANSI code page 切换为 UTF-8；`deploy_dlls.cmake` 是独立 `-P` 调用的脚本，仅复制 PDB 符号。
- `static_check/`：纯 Python 静态检查工具 + CMake 特性探测。`cpp_analyzer.py` 基于 `pathspec` 解析 `.gitignore`，扫描 C/C++ 源码检测 catch-all 异常、`using namespace`、不安全函数、魔法数字、潜在内存泄漏（new/malloc/free 配对）、圈复杂度，并以相对路径输出结构化 issue；`clang-format-batch.py` 实现自研 `.gitignore` 解析器，使用 `ThreadPoolExecutor` 并行调用外部 `clang-format -i` 进行批量格式化；`feature_check.cmake` 封装若干 `check_cxx_source_compiles` 辅助函数（concepts、ranges、source_location、NTTP class/fp、template-template matching、coroutines、explicit this、C++ modules、C23 constexpr），供上层根据编译器能力开关可选特性。
- `scripts/`：独立的文档流水线脚本 `repowiki_to_github_wiki.py`，读取 `.qoder/repowiki/{en,zh}/content` 下的 Markdown，扁平化目录为 GitHub Wiki 兼容页名，生成 `Home.md`/`_Sidebar.md`/`_Footer.md` 并支持语言切换。

依赖方向单向向外：本模块不引用项目源码，仅被顶层 CMake 和 CI 流程调用。
