顶层 `CMakeLists.txt` 是唯一的编排点：先执行 `static_check/feature_check.cmake` 探测 C++20 concepts/ranges/source_location/NTTP 等能力并注入 `HSBA_HAS_*` 宏，再根据 `VCPKG_TARGET_TRIPLET` 判定桌面/移动/游戏主机，依据 `HSBA_COPL`（AUTO/ON/OFF）决定是否启用 CGAL/OpenCascade 并切换 MIT/GPL-3.0-or-later 许可证；随后按固定顺序 `add_subdirectory` 引入 base → cipher → utils → logger → 2D → paths → fileoperator → meshmodel/(cadmodel) → pointcloud → preprocess → support → pipelinetypes → convert → LibHsBaSlicer → ModuleHsBaSlicer → DllHsBaSlicer → HsBaSlicer → version，最后可选地加入 samples、tests、static_tests、docs。

跨子模块的统一契约由三层构成：
1) ABI 层：`proto/pipeline_types.h`（protobuf 生成）+ `DllHsBaSlicer/dllexport.h` 暴露纯 C API，供 C#/Java/Python/Lua 调用；
2) 运行时桥接层：`utils` 提供 Lua/AnyObject/DLL 加载，`fileoperator` 提供 PipelineConfig 反射序列化，`convert` 在 Eigen/FullTopoModel/PipelineConfig 之间做双向转换；
3) 扩展点：模型后端（IGL/CGAL/OCCT/OpenVDB）、支撑生成器、路径输出格式均通过接口 + DLL/SO 插件机制在运行时发现。

所有静态库默认开启 `-fPIC`，最终通过 `install(EXPORT HsBaSlicerTargets ... NAMESPACE HsBaSlicer::)` 导出 CMake package config，供外部项目 `find_package(HsBaSlicer)` 引用。
