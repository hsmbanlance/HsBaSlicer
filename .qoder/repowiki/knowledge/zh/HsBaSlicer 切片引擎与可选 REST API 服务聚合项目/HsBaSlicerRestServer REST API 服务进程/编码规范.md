- HTTP 响应统一经由 `ReplyBody`/`ReplyValue`/`ReplyError` 三个 helper 生成，所有端点不再直接操作 `Response::set_content`。
- 数据格式协商通过 `TargetFormat(req, cfg)` 从 `?format=`、`Accept` 头与 `cfg.default_format` 三者决定，请求侧则用 `RequestBodyFormat(Content-Type)` 解析入参。
- 对外可见的 POD 视图结构体（HealthView、JobStatusView、ParamView、Index、KindList 等）定义在 `routes.cpp` 命名空间作用域，以便 `SerializeValue` 通过反射直接序列化为 JSON/XML。
- 对 DllHsBaSlicer 的配置对象一律走 `CreateDefaultConfig` + `DestroyConfig` 生命周期，字符串字段由调用方传入的 `StringArena` 管理，禁止跨 DLL 边界传递 C++ 容器。
- 异步作业通过 `JobManager` 的 `Runner` 函数指针抽象，默认绑定 `pipeline_executor::RunPipeline`，测试时可注入 mock 以绕过真实模型执行。
- 错误路径统一返回带 `Error` 根节点的 JSON/XML 负载（含 status/message/detail），HTTP 状态码根据语义区分 400/404/409/429/503/500。
