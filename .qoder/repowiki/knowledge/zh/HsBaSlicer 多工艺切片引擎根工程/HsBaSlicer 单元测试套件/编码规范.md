- 每个测试文件顶部定义 `#define BOOST_TEST_MODULE <name>` 并 `#include <boost/test/included/unit_test.hpp>`，使用 `BOOST_AUTO_TEST_SUITE` 与 `BOOST_AUTO_TEST_CASE` 组织用例。
- CMake 中每个测试目标遵循固定三段式：`add_executable` → `target_link_libraries(... Boost::unit_test_framework)` → `enable_testing()` + `add_test(NAME ... COMMAND $<TARGET_FILE:...>)`，并通过 `target_compile_definitions(<name> PRIVATE BOOST_TEST_DYN_LINK)` 启用动态链接。
- 可选测试通过 CMake 变量（`HSBA_COPL`、`HSBA_POLYGON_DUMP`、`HSBA_RUN_TESTS_AFTER_BUILD`）或 `if(TARGET HsBaSlicerCADModel)` 条件包裹，使缺失的外部依赖不会阻断整体构建。
- 跨 DLL 边界的测试将 mock 二进制路径通过 `MOCK_CAD_DLL_DIR` 宏或平台后缀（`.dll`/`.dylib`/`.so`，debug 版带 `_d`）解析，以适配不同构建配置下的 DLL 命名。
- Lua 驱动的测试通过相对 `__FILE__` 的路径定位同目录 `.lua` 脚本（如 `custom_fill.lua`），并以字符串字面量形式内联备用脚本源码调用 `LuaCustomFillString`。
