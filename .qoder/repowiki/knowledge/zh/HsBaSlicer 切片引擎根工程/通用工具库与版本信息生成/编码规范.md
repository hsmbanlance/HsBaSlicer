- Lua 对象绑定采用 CRTP 三层基类：抽象接口 `LuaAnyObjectNewCastBase`、CRTP 公共实现 `LuaAnyObjectNewCastAbstract`、具体模板特化 `LuaAnyObjectNewCastImpl<T, TypeName>`，新增类型只需继承并实现 `type_name_impl` / `new_func_impl` / `cast_func_impl`。
- Lua 侧暴露的函数名遵循 `new_<TypeName>` / `cast_<TypeName>` 命名约定，由 CRTP 基类根据 `type_name_impl()` 自动拼接。
- 所有 Lua 回调中异常通过 `lua_pushstring` + `lua_error` 抛出，并在注释中明确使用 `cast_new<T>()` 避免 `_gc` 元方法中的双重析构。
- Lua userdata 的生命周期通过 `NewLuaObject` 分配 + `LuaGC` 作为 metatable 的 `__gc` 钩子释放，配合 `UniqueLua` / `LuaStateDeleter` 用 RAII 管理 `lua_State`。
- 序列化实现以 C++20 concept（`Aggregte` / `Reflectable`）约束模板参数，分别对应 JSON、XML、YAML 三个独立头文件，保持同一接口不同后端。
- 全局可访问状态通过带 `shared_mutex` 保护的静态单例类（如 `AppConfigSingletone`）暴露，并提供 `GetInstance` / `DeleteInstance` 成对接口。
