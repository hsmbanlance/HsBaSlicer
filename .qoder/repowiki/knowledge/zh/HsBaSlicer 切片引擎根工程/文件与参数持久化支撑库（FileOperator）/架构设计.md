模块以 CMake 静态库 `HsBaSlicerFileOperator` 形式聚合，按职责划分为四个子层：
- 归档抽象层：`IZipper.hpp` 定义纯虚接口，`zipper.cpp` 通过 miniz 实现 `Zipper`；解包侧采用 CRTP 基类 `IUnzipper<Derived>` + `UnzipperStream`（封装 `std::ifstream` / `std::istringstream`），由 `unzipper.cpp`（miniz 实现）和可选的 `bit7z_unzipper.cpp`（Bit7z 实现）分别提供。
- SQL 适配层：`sql_adapter.hpp` 在 `HsBa::Slicer::SQL` 命名空间内声明 `ISQLAdapter` 接口及 `SQLiteAdapter` / `MySQLAdapter` / `PostgreSQLAdapter` 三个 PIMPL 实现，并通过 `operator|` 管道语法暴露 `SQLSelect`/`SQLInsert`/`SQLUpdate`/`SQLDelete`/`SQLCreateTable`/`SQLRemoveTable` 等结构体。
- 参数持久化层：`param_store.cpp/.hpp` 作为入口，组合 `param_schema`（表结构注册）、`param_reflect`（AnyObject 字段遍历）、`param_convert`（类型转换）、`sql_adapter`（CRUD），对每个 `PipelineConfig` 类型维护一张宽表，提供 EnsureSchema / Save / Load / List / Update / Delete 全量 CRUD，批量 API 包裹事务，错误通过 `last_error_` 记录并抛出异常。
- Lua 绑定层：`LuaAdapter.cpp` 集中注册 Zipper、Unzipper、各 SQL Adapter 与 ParamStore 到 Lua 全局表，条件编译开关 `HSBA_USE_BIT7Z` / `HSBA_USE_MYSQL` / `HSBA_USE_PGSQL` 控制 Bit7z 与各数据库绑定的可见性。
依赖方向单向向下：LuaAdapter → (Zipper/Unzipper/ParamStore) → sql_adapter → 底层库；CMakeLists.txt 中通过 `HSBA_HSBA_USE_BIT7Z`、`HSBA_GAME_CONSOLE`、Android/iOS 宏裁剪 bit7z、Boost.log、sqlpp11 的多后端链接。
