模块由三个相互协作的子目录组成，形成「协议定义 → 外部 ABI → 运行时转换」三层结构：
- `proto/`：基于 proto3 的数据契约层，按领域划分文件（`point.proto`/`vector.proto`/`transform.proto`/`path.proto` 为几何基元；`mesh.proto` 描述三角网格与拓扑网格；`*_pipeline.proto` 对应 FDM/SLA/SLS/SLM/LOM/TDP/WAAM/FileTransfer/Custom 等流水线配置与结果；`base_config.proto`/`slice_config.proto`/`boolean_operation.proto`/`custom_pipeline.proto` 提供共享字段）。`CMakeLists.txt` 通过 `PROTOBUF_GENERATE_CPP` 生成 C++ 头/源并打包为静态库 `HsBaSlicerProto`，同时支持通过 `HSBA_PROTOBUF_OUT_*` 选项向多语言目录输出 C#/Java/Python/PHP 源码。
- `pipelinetypes/`：纯头文件 INTERFACE 库 `HsBaPipelineTypes`，在 `pipeline_types.h` 中以 `extern "C"` 暴露所有流水线（FDM/SLA/SLS/SLM/LOM/TDP/WAAM/FileTransfer/Custom）的 C 兼容 enum/struct/callback/result，并提供 `HsBa*ConfigDefault()` 内联初始化器，刻意不依赖 `DllHsBaSlicer` 或 `dllexport.h`，以便下游（如 convert、Lua 绑定）直接包含。
- `convert/`：静态库 `HsBaSlicerConverter`，提供三组双向转换器：`Eigen2Msg`/`Msg2Eigen`（Eigen 几何类型 ↔ protobuf 几何消息）、`FullTopoModel2Msg`/`Msg2FullTopoModel`（内部拓扑模型 ↔ protobuf mesh）、`PipelineConfig2Msg`/`Msg2PipelineConfig`（`HsBaPipelineTypes` 中的 C struct ↔ protobuf pipeline config）。该库依赖 `HsBaSlicerProto`、`HsBaSlicerMesh` 和 `HsBaPipelineTypes`，是连接 C++ 运行时与序列化协议的桥梁。
依赖方向单向：convert → (proto + pipelinetypes)，proto 与 pipelinetypes 之间无运行时依赖。
