三个文件分别实现一种工艺（fdm/sla/slm），结构高度同构：
- 每个文件在匿名命名空间内定义 `Internal*Config` / `Internal*Result` 内部结构体以及 `Build*Config`、`ToCResult`、`OwnedCString` RAII 包装器，将外部 C ABI 类型与内部 C++ 对象解耦。
- 核心工作流由 `RunXxxPipelineAsync` 协程驱动，按 Stage 1~5（Preprocess → Slicing → Support/Floor/Infill → Path/Export）顺序推进，通过 `ReportProgress` 回调上报进度；异常统一捕获 `RuntimeError` 并转为失败结果。
- 依赖方向单向指向 `LibHsBaSlicer/*`（model_preprocess、mesh_slice、Fill、Support、Path、Floor、Sls_export）以及本模块的 `pipeline_parallel.hpp` 提供的 `ParallelForLayers` 并行化原语；Lua 扩展点通过 `InstallCommonAnyObjectTypes` + `LuaCustom*ByFile` 注入到各阶段的 Lua 解释器中。
- 对外仅暴露 `HSBA_SLICER_API` 标记的 C 函数：`HsBaCreateDefault*Config`、`HsBaRun*XxxPipeline`（同步阻塞）、`HsBaRun*XxxPipelineAsync`（基于 `Utils::Task` 的 then 回调）、`HsBaFree*XxxPipelineResult`（释放 malloc 字符串）。异步调用时配置被 `std::make_shared` 堆分配以跨越协程生命周期。
- 工艺差异集中在具体阶段：FDM 走 FillWithBorder + GenerateGCodePathV2/Spiral 输出 G-code；SLA 走 FloorRaft + SlaPackage 导出 zip；SLM 强制要求 Lua export 脚本并通过 SlsPackage 复用 SLS 打包格式。
