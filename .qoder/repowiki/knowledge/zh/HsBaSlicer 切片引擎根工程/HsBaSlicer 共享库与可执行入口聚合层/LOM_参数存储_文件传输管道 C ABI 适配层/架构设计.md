三个 .cpp 文件同属 `HsBa::Slicer::Pipeline` 命名空间下的 C ABI 适配层，统一遵循“内部结构 + Build*Config + Run*Async 协程 + ToCResult + HSBA_SLICER_API 导出”的分层模式：
- lom_pipeline.cpp：实现 LOM 流水线，按阶段（加载模型→并行切片 ParallelForLayers→Lua 脚本导出 SaveSlsPackageLua）编排，使用 `InternalLomConfig`/`InternalLomResult` 在 C 结构与内部类型间转换，并通过 `OwnedCString` 管理 `export_path`/`error_message` 的堆分配。
- param_store_pipeline.cpp：不直接执行业务逻辑，仅做 C 枚举到 LibHsBaSlicer 枚举的显式映射（ToLibKind/ToLibBackend/ToLibConn），调用 `SavePipelineParams`/`LoadPipelineParams`/`FreeLoadedConfigStrings`，并提供 `DupToHeap` 复用字符串复制逻辑。
- file_transfer_pipeline.cpp：将 `HsBaFileTransferPipelineConfig_t` 转为 `FileTransferConfig`，委托 `TransferFiles` 完成实际传输，并桥接 `FileTransferProgressFunc` 到 C 回调。
依赖方向单向指向 `LibHsBaSlicer`（Slice/ParamStore/Transfer）与 `base/coroutine.hpp`、`base/error.hpp`；所有对外符号通过 `HSBA_SLICER_API` 暴露，同步 API 内部阻塞 `.get_result()`，异步 API 通过 `task.then` 回调释放结果。
