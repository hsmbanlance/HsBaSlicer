Built as the `HsBaSlicerUtils` static library via `utils/CMakeLists.txt`, composed of four orthogonal sub-areas with no internal dependencies between them:

- Graph algorithms (`Graph.hpp`, `AreaGraph.hpp`): header-only typed wrappers over Boost.Graph (`BaseGraph`/`DirectedGraph`/`UndirectedGraph`) exposing vertex/edge id maps plus a `graph::algorithm` namespace with BFS/DFS, Dijkstra, Bellman-Ford, A*, Prim/Kruskal MST, connected/strong components, topological sort, Boykov-Kolmogorov max-flow, and a genetic TSP solver.
- Lua bridge (`LuaAnyObject.{hpp,cpp}`, `LuaNewObject.hpp`, `LuaDllLoader.{hpp,cpp}`): CRTP-based adapter framework (`LuaAnyObjectNewCastBase` → `LuaAnyObjectNewCastAbstract` → `LuaAnyObjectNewCastImpl<T, TypeName>`) that exposes native types to Lua through `new_<type>` / `cast_<type>` functions registered via `RegisterAnyObject`; `DllLoader` wraps `boost::dll::shared_library` and generates per-signature `lua_dll_get_function`/`lua_dll_call_function` bindings via `LuaDllGetFunction<TName, Ret, Args...>`, gated by `HSBA_NO_DLL_LOADER`.
- Structured data I/O (`struct_concepts.hpp`, `struct_json.hpp`, `struct_xml.hpp`, `struct_yaml.hpp`): C++20 concepts (`Aggregte`, `Reflectable`) gate dispatch between Boost.PFR-based aggregate serialization and the project's `StaticReflect` system; three parallel serializers target RapidJSON, tinyxml2, and yaml-cpp respectively, all under `HsBa::Slicer::Utils`.
- Application config (`app_config.{hpp,cpp}`): thread-safe singleton (`AppConfigSingletone`) guarding shared settings like the 7-Zip path behind a `std::shared_mutex`.

Dependency direction is outward only: this module depends on `HsBaSlicerBase`, `HsBaSlicerFileOperator`, Boost (date_time, dll, container_hash, graph), rapidjson, tinyxml2, yaml-cpp, and Lua; nothing inside the module depends on higher-level slicer domains.
