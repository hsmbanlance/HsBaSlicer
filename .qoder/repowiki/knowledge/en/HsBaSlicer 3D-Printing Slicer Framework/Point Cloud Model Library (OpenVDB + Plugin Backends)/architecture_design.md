Two interchangeable `IModel` backends live side-by-side in this static library:
- `OpenVdbModel` (OpenVdbModel.hpp/.cpp plus split implementation files: internal.h, mesh.cpp for level-set reconstruction, analysis.cpp for KNN/normal estimation) stores points in an `openvdb::Vec3fGrid` and implements all transform/bound/mesh operations on top of it.
- `UserCustomPointCloudModel` wraps a dynamically loaded plugin via `UserCustomPointCloudDll`, which resolves a fixed C ABI (`IUserCustomPointCloud` typedefs such as `CreateModelFunc`, `AddPointsFunc`, etc.) exported from a user-supplied DLL/SO; the two classes expose the same public API so plugins are drop-in replacements for the built-in kernel.

Dependency direction is one-way outward: this module depends on `HsBaSlicerBase` (for `IModel`, `ModelFormat`, `HsBaVector3f_t`) and third-party libraries discovered at build time. The CMakeLists.txt compiles everything into the `HsBaSlicerPointCloud` static target, conditionally linking OpenVDB (with blosc/ZLIB/Boost::iostreams), TBB, Imath, and Boost::dll (desktop only). MSVC builds add `/bigobj` to `OpenVdbModel_mesh.cpp` to work around the 65535-section limit from heavy level-set templates.
