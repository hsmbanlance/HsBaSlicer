Each subdirectory under `tests/` corresponds to a production module (e.g. `AnyObject`, `ConfigMap`, `PathsOut`, `PolygonFill`, `Models`, `Support`) and contains one or more `*_test.cpp` files that compile into individual Boost.Test executables. The single `tests/CMakeLists.txt` is the build manifest: it calls `find_package(Boost ... unit_test_framework)`, then for every test defines an `add_executable(...)` target, links it against the relevant `HsBaSlicer*` libraries plus third-party deps (`Eigen3::Eigen`, `${LUA_LIBRARIES}`, `Boost::unit_test_framework`), sets `BOOST_TEST_DYN_LINK`, calls `enable_testing()` and `add_test(NAME ... COMMAND $<TARGET_FILE:...>)`, and optionally wires a POST_BUILD `ctest -R` via the `HSBA_RUN_TESTS_AFTER_BUILD` flag. A central `ALL_TEST_TARGETS` list aggregates all targets and feeds a `RunAllTests` custom target. Conditional compilation gates exist for optional features: OCCT tests only when `HsBaSlicerCADModel` exists, CGAL tests only when `HSBA_COPL` is set, Lua-polygon tests only when `HSBA_POLYGON_DUMP` is enabled, and MSVC-specific `/bigobj` for the heavy `Graph/graph_test.cpp`. Some tests ship companion mock DLLs (`mock_cad_dll.cpp`, `mock_dll_loader_dll.cpp`, `mock_point_cloud_dll.cpp`) and embedded Lua scripts (`custom_fill.lua`, `image_from_polygons.lua`, `optimize_paths.lua`) to exercise dynamic loading and scripting paths.
