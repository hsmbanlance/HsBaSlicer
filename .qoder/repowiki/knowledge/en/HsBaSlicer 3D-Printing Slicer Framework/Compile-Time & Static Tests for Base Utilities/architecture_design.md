Two sibling CMake subprojects under `static_tests/`, each a standalone executable whose only purpose is to include the headers under test so that `static_assert` failures become build failures.
- `base_static_tests/base_static_tests.cpp` exercises `base/template_helper.hpp`, `base/any_visit.hpp`, `base/tuple_each.hpp`, `base/coroutine.hpp`, and `base/any_object.hpp`, covering enum name mapping, `NamedRawPtr`, `template_call`, `AllValidEnum`, `Visit`/`Overloaded`, `TupleEach`, `Task`/`Generator` coroutines, and runtime-type registration via `GetTypeInfo<T>` specializations.
- `utils_static_tests/utils_static_tests.cpp` exercises `utils/struct_json.hpp`, `struct_xml.hpp`, `struct_yaml.hpp`, `utils/LuaNewObject.hpp`, and `utils/LuaAnyObject.hpp`, validating JSON/XML/YAML round-trips on both plain structs and reflection-declared classes (`FieldList`/`MethodList`/`ClassName`).
The parent `CMakeLists.txt` simply `add_subdirectory`s both; there is no shared test harness — each `.cpp` file is self-contained and relies on `static_assert` plus conditional `#if __cpp_lib_coroutine && __cpp_impl_coroutine` blocks.
