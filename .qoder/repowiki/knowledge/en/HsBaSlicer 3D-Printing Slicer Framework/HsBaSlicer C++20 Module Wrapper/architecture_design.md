Three-file leaf built as a STATIC CMake library (`ModuleHsBaSlicer`).
- `hsba_slicer.cppm` is the single-file C++20 module interface unit: it declares the exported `module hsba.slicer`, the `HsBa::Slicer` namespace (exception, type aliases re-exported from Clipper2/Eigen/pipelinetypes, RAII `Model`, one pipeline class per process type, `ParamStorePipeline`, `CustomLuaPipeline`, Lua registration helpers, version/utilities), and defines all inline bodies in the same translation unit to avoid MSVC C2572 implicit-import std:: redefinition errors.
- `module_anchor.cpp` is an intentionally empty TU under `HsBa::Slicer::detail` whose sole purpose is to force the archiver to emit `ModuleHsBaSlicer.lib` when the only sources are CXX_MODULES file sets.
- `CMakeLists.txt` wires the module via `target_sources(... FILE_SET hsba_slicer_modules TYPE CXX_MODULES ...)` and links PUBLIC against `LibHsBaSlicer`, `HsBaPipelineTypes`, Eigen3, Clipper2, and Lua; it also re-exports CGAL's `/fp:strict /fp:except _SCL_SECURE_NO_WARNINGS` compile flags so BMI consumers see identical settings.
Dependency direction is one-way: this wrapper depends on `LibHsBaSlicer` and shared project headers (`pipelinetypes`, `2D`, `meshmodel`, `paths`, `support`) but exposes no C ABI — consumers import the module and link the static archive.
