- Each process type (FDM, SLA, SLS, SLM, LOM, TDP, WAAM) is exposed as a dedicated pipeline class in `HsBa::Slicer` with a constructor taking its typed config struct and a `run(const Model&)` method that slices layers, builds a package, and delegates export to the corresponding LibHsBaSlicer function.
- Lua-driven pipelines validate that `cfg_.export_lua_script` is set at the top of `run()` and throw `SlicerError("... requires export_lua_script")` before any processing begins.
- Layer iteration follows a uniform pattern: compute `height = bbox_max.z() - bbox_min.z()`, derive `layers = height / cfg_.layer_height + 1`, then loop `i` computing `z = first_layer_height + i * layer_height` and pushing `UnIntegerization(Slice(model.raw(), z))` into a pre-reserved vector.
- Optional algorithm stages (support generation, fill, floor, export) branch on a `*_lua_script` config field to dispatch between the built-in implementation and the Lua variant (`GenerateAllLuaSupport`, `LuaCustomFillByFile`, `SaveSlaPackageLua`, etc.), falling back to the native path when unset.
- Configuration structs are constructed by mapping each `cfg_` member onto the corresponding Lib-layer struct field-by-field (e.g. FDM support config, printer config, SLA floor config) rather than passing the raw config through.
