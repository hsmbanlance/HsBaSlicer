The module is a flat collection of independent tooling assets grouped by purpose:
- `cmake/` provides CMake modules consumed by the top-level build: `HsBaSlicerConfig.cmake.in` is the package-config template declaring public dependencies (Eigen3, magic_enum, Clipper2, Lua, Protobuf, OpenSSL) and including generated targets; `coverage.cmake` instruments all targets with `--coverage`, drives gcovr in two passes (dump → gate), enforces per-bucket line-coverage thresholds (`HSBA_COVERAGE_THRESHOLD_CORE`/`OTHER`), and exposes a `coverage` custom target; `deploy_dlls.cmake` is a standalone scriptlet invoked via `cmake -P` to copy PDB symbols next to executables.
- `static_check/` holds three orthogonal tools: `cpp_analyzer.py` (a self-contained Python linter using `pathspec` for `.gitignore` matching that detects catch-all exceptions, `using namespace`, unsafe functions, magic numbers, manual `new`/`malloc` without paired release, and cyclomatic complexity); `clang-format-batch.py` (parallel `clang-format` runner with its own `.gitignore` parser and `ThreadPoolExecutor`); `feature_check.cmake` (C/C++ feature probes via `check_cxx_source_compiles` for concepts, ranges, source_location, NTTP class/fp, template-template matching, coroutines, explicit-this, C++20 modules, C23 constexpr).
- `scripts/repowiki_to_github_wiki.py` converts `.qoder/repowiki/{en,zh}` markdown into GitHub Wiki pages plus `Home.md`/`_Sidebar.md`/`_Footer.md`.
- `overlay-ports/` and `triplets/` are vcpkg extension directories whose READMEs document where to drop custom ports and triplets respectively.
Dependency direction is one-way: scripts and CMake modules depend only on standard libraries or external tools (gcovr, clang-format, pathspec); nothing in this module depends on the project's C++ sources.
