Three complementary headers form the public boundary of the pipeline subsystem:
- `custom_pipeline.h` declares the C ABI (`extern "C"`, `HSBA_SLICER_API`) for creating, running (sync + async via C++20 coroutines), and freeing fully Lua-driven custom pipelines; it depends on `pipelinetypes/pipeline_types.h` for the shared config/result structs.
- `pipeline_convert.h` is a pure conversion surface: for each pipeline family (FDM, SLA, SLS, FileTransfer, CustomLua, SLM, LOM, 3DP, WAAM) it exposes paired `*FromProtoBytes` / `*ToProtoBytes` functions that marshal between protobuf wire format and the C structs, plus per-family `HsBaFree*ConfigStrings` helpers for malloc'd string fields. All output buffers are `malloc`-allocated and caller-owned.
- `pipeline_parallel.hpp` is a header-only utility in `HsBa::Slicer::Pipeline` exposing `ParallelForLayers`, which dispatches independent per-layer work over a `base::ThreadPool`, batches futures to keep progress callbacks serial on the calling thread, and falls back to a serial loop when threads or layers ≤ 1. Worker count is tunable via the `HSBA_PIPELINE_THREADS` environment variable for perf validation.

Dependency direction is one-way: this module consumes `pipelinetypes` and `base/thread_pool.hpp`; nothing inside these three files reaches into the concrete pipeline implementations — they only expose types, conversions, and execution primitives.
