Children are layered rather than peer modules: `shared_infrastructure` provides the DLL load-time bootstrap (`initialize.cpp`, `event_source_register.cpp`, `lua_register.cpp`) that registers Lua functions and event-source callbacks; `pipeline_framework` defines the stable C ABI (proto types, parallel-for helper) that every other child implements; `model_preprocess` wraps LibHsBaSlicer geometry operations behind the same C ABI so pipeline children can call back into geometry without depending on the Rust crate directly; `process_pipelines`, `powder_bed_pipelines`, and `waam_and_file_transfer` each implement one or more of the C-ABI pipeline entry points (FDM/SLA/LOM/SLS/SLM/3DP/WAAM/file-transfer/param-store/custom). A single `CMakeLists.txt` builds them into one DLL, and the host discovers capabilities via the registered Lua/event surface rather than linking individual pipeline symbols.
