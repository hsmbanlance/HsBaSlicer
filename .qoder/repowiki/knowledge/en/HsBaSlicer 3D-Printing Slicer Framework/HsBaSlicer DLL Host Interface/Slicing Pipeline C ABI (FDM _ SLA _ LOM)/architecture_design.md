Three sibling files each implement one printing technology (FDM, SLA, LOM) under namespace `HsBa::Slicer::Pipeline`, sharing an identical internal layout:
- A private `Internal*Config` struct mirrors the public C config type and holds raw C++ types plus a `progress_cb`/`progress_user_data` pair.
- An anonymous-namespace helper `OwnedCString` owns `malloc`-allocated C strings so they are freed on exception or early return; `ToCResult` copies fields into the C result via this guard.
- `Build*Config` translates the C ABI struct into the internal config; `Run*PipelineAsync` is a `Utils::Task<Internal*Result>` coroutine that runs the pipeline and returns via `co_return`.
- The synchronous C entry (`HsBaRun*Pipeline`) calls `task.get_result()`; the async entry (`HsBaRun*PipelineAsync`) heap-allocates the config via `std::make_shared` to survive coroutine lifetime and wires `task.then(...)` to a user-supplied result callback.
- Each pipeline follows a fixed stage sequence: Preprocess (model load via `GetModel`/`LoadModel` + `GetModelInfo`), Slicing (`BuildSliceTopology` + `ParallelForLayers` over `SliceLayer`), then technology-specific stages (FDM: support → infill → path generation producing G-code; SLA: floor/raft → support → `SlaPackage` export; LOM: contour-only slicing → `SlsPackage` export via Lua). Parallelism uses `ParallelForLayers` from `pipeline_parallel.hpp`; Lua-based custom support/infill/floor/export is invoked through `GenerateAllLuaSupport`, `LuaCustomFillByFile`, `LuaCustomFloorByFile`, `SaveSlaPackageLua`, `SaveSlsPackageLua`. All three call `InstallCommonAnyObjectTypes()` at coroutine start to register shared Lua types. Errors propagate as `RuntimeError` caught by a single try/catch block that sets `success=false` and formats the message.
