The module is a static CMake library (`HsBaSlicerFileOperator`) organized into four cohesive sub-areas:

- Archive layer: `IZipper.hpp` defines a pure-virtual `IZipper` interface; `zipper.cpp` implements it with miniz as `Zipper`, while `IUnzipper.hpp` provides a CRTP base `IUnzipper<Derived>` plus an `UnzipperStream` that wraps either an in-memory buffer or a temp file. Two backends exist — `bit7z_zipper.cpp` / `bit7z_unzipper.cpp` (optional, gated by `HSBA_HSBA_USE_BIT7Z`) and the default miniz-based `zipper.cpp` / `unzipper.cpp`. Both are exposed to Lua through `LuaAdapter.cpp`.
- SQL layer: `sql_adapter.hpp` declares `ISQLAdapter` and concrete `SQLiteAdapter`, `MySQLAdapter`, `PostgreSQLAdapter` (the latter two guarded by `HSBA_USE_MYSQL` / `HSBA_USE_PGSQL`). Each adapter uses PIMPL + `std::shared_mutex` for thread safety and derives from `Utils::EventSource` for progress callbacks. A fluent pipe-operator DSL (`operator|`) over `SQLSelect` / `SQLInsert` / `SQLUpdate` / `SQLDelete` / `SQLCreateTable` / `SQLRemoveTable` composes queries.
- Parameter persistence: `param_schema.*` / `param_reflect.*` / `param_convert.*` / `param_store.*` form a reflection-driven pipeline that maps `PipelineConfig` structs to wide tables per type, exposing CRUD (`EnsureSchema` / `Save` / `Load` / `List` / `Update` / `Delete`) on top of any `ISQLAdapter`. `properties_doc.*` and `rw_ptree.*` support property-document serialization.
- Remote execution: `RemoteExecutor.{hpp,cpp}` exposes `RemoteExecutorConnection` and a round-robin `RemoteExecutorConnectionPool` for bulk file upload to a remote service.

Dependency direction is one-way outward: LuaAdapter depends on all other subsystems; ParamStore depends on sql_adapter; archive implementations depend only on the interfaces and miniz/bit7z. Conditional compilation gates optional features at both link time (CMake) and source level (`#ifdef HSBA_USE_*`).
