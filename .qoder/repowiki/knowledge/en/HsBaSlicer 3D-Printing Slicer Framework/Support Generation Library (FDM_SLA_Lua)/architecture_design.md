The module builds the static library `HsBaSupport` (see `CMakeLists.txt`) around a single abstract interface `ISupport` with a per-layer `Generate(current_layer, prev_layer, layer_height, config)` method plus a default `GenerateAll` loop. Concrete generators are split by technology: `FdmSupport.{hpp,cpp}` implements `FdmPlaneSupport`, `FdmTreeSupport`, and `FdmHoneycombSupport`; `SlaSupport.{hpp,cpp}` implements `SlaSacrificialSupport`; `LuaSupport.{hpp,cpp}` hosts an embedded Lua state that lets user scripts replace the built-in algorithm entirely. `OverhangDetector.{hpp,cpp}` is a shared utility used by all generators to compute overhang regions from current/previous layer polygons. Configuration is centralized in `SupportConfig.hpp` as a base `SupportConfig` struct extended by `FdmSupportConfig` and `SlaSupportConfig`. The Lua integration is isolated behind `LuaAdapter.{hpp,cpp}`, which registers a `Support` global table exposing constructors for each generator plus `detect_overhang` and `generate` helpers — Lua code never touches C++ classes directly. Dependency direction inside the module is one-way: concrete generators depend on `ISupport` + `SupportConfig` + `OverhangDetector`; only `LuaAdapter` depends on the concrete classes to expose them to Lua; nothing here depends on higher-level slicer orchestration beyond the shared `HsBaSlicerBase` / `HsBaSlicer2D` / `HsBaSlicerUtils` / Clipper2 libraries declared in `CMakeLists.txt`.
