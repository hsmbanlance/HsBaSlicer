Single C++ module under `logger/` exposing the `HsBa::Slicer::Log` namespace. The public surface is `LoggerSingletone`, a shared-ptr singleton built on `base/singleton.hpp` with `std::shared_mutex` + `std::once_flag` for thread-safe lazy initialization via `GetInstance()` / `CreateInstance()`. Platform-specific backends are selected at runtime inside the constructor: non-mobile platforms initialize Boost.Log with file+console sinks and rotation (50 MB / midnight), Android uses `__android_log_print`, iOS uses `os_log_create` + `os_log_with_type`. Configuration is loaded from `<cwd>/logcfg.ini` via `fileoperator/rw_ptree.hpp` (`Config::from_ini`) into fields `log_path_`, `use_log_file_`, `log_level_`, `log_datatime_format_`. A fluent API lives in an inline sub-namespace `LogLiterals` offering user-defined literals `_log_debug/_log_info/_log_warning/_log_error` that return a `LogState` whose destructor invokes `LoggerSingletone::Log` with auto-captured `std::source_location`. Symbol visibility is controlled by `export.h`'s `HSBA_SLICER_LOG_API` macro, toggled by the `HSBA_SLICER_LOG_EXPORTS` compile definition set by `CMakeLists.txt` when building the SHARED target `HsBaSlicerLog`.

Dependency direction: this module depends inward on `base/singleton.hpp` and `fileoperator/rw_ptree.hpp`; nothing in the rest of the tree should depend on Boost.Log directly — they go through this facade instead.
