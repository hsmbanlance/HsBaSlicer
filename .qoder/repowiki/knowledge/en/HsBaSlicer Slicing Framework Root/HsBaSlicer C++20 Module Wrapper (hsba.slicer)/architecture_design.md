Single-file C++20 module (`hsba_slicer.cppm`) split into an interface section (declarations, type aliases, public classes under `export namespace HsBa::Slicer`) and an implementation section in the same file; a tiny `module_anchor.cpp` is included only to force CMake's archiver to emit `.lib` for a static library whose only source is a `FILE_SET CXX_MODULES`. Dependency direction is one-way outward: every method forwards to free functions in `LibHsBaSlicer` (e.g. `LoadModel`, `Slice`, `GenerateAllFdmSupport`, `FillWithBorder`, `GenerateGCodePathV2`, `SaveSlsPackageLua`). Public surface is organized as:
- `Model` — RAII handle around a pooled `IModel*` with move-only semantics and transform/slice operations.
- Per-process pipeline classes (`FdmPipeline`, `SlaPipeline`, `SlsPipeline`, `SlmPipeline`, `LomPipeline`, `TdpPipeline`, `WaamPipeline`, `FileTransferPipeline`, `ParamStorePipeline`, `CustomLuaPipeline`) each holding a single config struct and exposing a `run(Model&)` entry point plus optional stage-level helpers.
- Lua extension points (`add2DFunction`, `add3DFunction`, `addFileFunction`, `addEventCallback`, `addZipperEventCallback`, `addDBEventCallback`) that plug into the embedded Lua runtime via `Add2DFunctions`/`Add3DFunctions`/`AddFileFunctions`/`AddEventCallback`.
- `ParamStorePipeline` bridges the consumer-facing `ParamStoreKind`/`ParamStoreBackend` enums to Lib-layer `ParamPipelineKind`/`ParamBackend` through anonymous-namespace converters (`ToLibKind`, `ToLibBackend`, `ToLibConn`).
Type aliases re-export Clipper2 types and all `HsBaXxxPipelineConfig_t` / `HsBaXxxPipelineResult_t` structs into `HsBa::Slicer` so consumers never include `pipelinetypes/pipeline_types.h` directly.
