Single-file C++ entry module (`HsBaSlicer.cpp`) with a minimal umbrella header (`HsBaSlicer.h`). It depends on three sibling targets linked via `CMakeLists.txt`: `HsBaSlicerUtils`, `HsBaSlicerLog`, and the core slicing engine `DllHsBaSlicer` (including `fdm_pipeline.h`, `sla_pipeline.h`, `sls_pipeline.h`, `initialize.h`). The file provides one static helper per platform: a JNI function `Java_com_hsmbanlance_hsbaslicer_example_MainActivity_runPipelineExamples` on Android, an exported `HsBaRunPipelineExamples` on iOS, and a standard `main()` on macOS/Desktop. Each platform path calls `initialize()`, configures logging through `HsBa::Slicer::Log::LoggerSingletone`, then sequentially invokes `RunFdmExample` / `RunSlaExample` / `RunSlsExample`, which build a typed config struct, call the corresponding `HsBaRun*Pipeline` API, write results to disk, and free memory via the matching `HsBaFree*Result` function. `CMakeLists.txt` switches the target type between SHARED (Android), STATIC (iOS), and EXECUTABLE (desktop) and adds post-build steps to copy PDBs on Windows and `.so` files on Android.
