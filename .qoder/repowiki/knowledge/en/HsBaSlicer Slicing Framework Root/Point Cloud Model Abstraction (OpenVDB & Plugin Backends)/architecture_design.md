Two interchangeable `IModel` implementations live side-by-side under `HsBa::Slicer`:
- `OpenVdbModel` (OpenVdbModel.hpp/.cpp) is the default kernel, storing points in an `openvdb::Vec3fGrid` and exposing point-cloud operations (voxelize, KNN/radius search, downsampling, centroid, merge, outlier removal, normal estimation). Heavy template-heavy mesh reconstruction (`GenerateMesh` via `particlesToSdf` → level-set smoothing → marching cubes) is isolated in `OpenVdbModel_mesh.cpp` to avoid MSVC's 65535-section limit.
- `UserCustomPointCloudModel` (UserCustomPointCloudModel.hpp/.cpp) is a thin wrapper around a dynamically loaded shared library. It defines the `IUserCustomPointCloud` ABI (function-pointer typedefs over `HsBaVector3f_t`) and a `UserCustomPointCloudDll` loader that resolves create/destroy/add/query symbols; the model delegates every operation through those pointers.
- Shared helpers (`OpenVdbModel_internal.h`) live in the internal `vdb_internal` namespace and provide path normalization and OpenVDB/Eigen adapters (`PointArrayAdapter`, `LevelSetParticleAdapter`, `ToCoord`/`ToEigen`).
- Dependency direction: both backends depend on `base/IModel.hpp`; only `OpenVdbModel` depends on OpenVDB, Eigen, TBB, Imath, and Boost; the plugin path is gated by `HSBA_NO_DLL_LOADER` and uses Boost.DLL on desktop builds. The CMake target `HsBaSlicerPointCloud` is static and conditionally links OpenVDB/blosc/ZLIB/Boost::iostreams when available.
