Flat header-plus-few-translations-unit layout under `base/` with two namespace layers:
- `HsBa::Slicer` holds cross-cutting abstractions: the `IModel` pure-virtual interface plus `ModelFormat` enum (PLY/OBJ/STL/OFF/VRML/STEP/IGES/BREP/SLDPRT/CATPART/XYZ/VDB) in `IModel.hpp`, a uniform exception hierarchy rooted at `RuntimeError` (`error.hpp`), C++20 concepts (`concepts.hpp`) reused across delegates/translators/containers, filename/string helpers, and the `base_interface.hpp` / `static_reflect.hpp` / `coroutine.hpp` primitives.
- `HsBa::Slicer::Utils` hosts reusable runtime primitives: `AnyObject` type-erased wrapper backed by per-type `TypeInfo` descriptors (destroy/copy/move functors + field/method maps) enabling reflective `Invoke`/`ForeachField`/`cast<T>()`; `Delegate` callback; `ThreadPool`, `Coroutine`, `MemoryPool`, `ObjectPool`, `Singleton`; `InplaceVector`.
- Heavy translation units (`any_object.cpp`, `modelformat.cpp`, `eigen_translator.cpp`, `encoding_convert.cpp`, `filename_check.cpp`, `error.cpp`) exist only where compilation-unit size or external linkage warrants it; everything else is header-only.
- External bridge files (`eigen_translator.*`, `boost_std_convert.*`) convert between Eigen/Boost/std types; `magic_enum` is used to specialise `enum_range<HsBa::Slicer::ModelFormat>` for stringification.
- Dependency direction is one-way inward: this module depends on Eigen, magic_enum, and optionally Boost; nothing outside should include into it. The `CMakeLists.txt` builds these `.cpp` files into the library target.
