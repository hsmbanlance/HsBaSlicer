Built as a single static CMake library `HsBaSlicerFileOperator` composed of four loosely coupled subsystems with one-way dependencies:

- **Archive layer**: `IZipper.hpp` defines an abstract `IZipper` interface; `zipper.cpp` (miniz-based) and `bit7z_zipper.cpp` (Bit7z, gated by `HSBA_HSBA_USE_BIT7Z`) implement it. Extraction uses a CRTP base `IUnzipper<Derived>` in `IUnzipper.hpp` with `UnzipperStream` as a type-erased `std::istream` over either an in-memory buffer or a temp file; concrete backends are `unzipper.cpp` (miniz) and `bit7z_unzipper.cpp` (Bit7z).
- **SQL + ParamStore pipeline**: `sql_adapter.hpp` declares `ISQLAdapter` plus `SQLiteAdapter`, `MySQLAdapter`, `PostgreSQLAdapter` (the latter two gated by `HSBA_USE_MYSQL` / `HSBA_USE_PGSQL`). Each adapter exposes a fluent pipe-operator DSL (`db | SQLSelect{...}` etc.). `param_schema.*` registers `PipelineConfig` types, `param_reflect.*` traverses them via `AnyObject::ForeachField`, `param_convert.*` coerces values, and `param_store.cpp`'s `ParamStore` composes these into a staged Validate→Reflect→Coerce→Upsert CRUD flow with transaction-wrapped batch APIs and optional AES-256-CBC at-rest encryption.
- **Config map helpers**: `rw_ptree.*` wraps `boost::property_tree` with typed `VariantConfigMap<T...>` and type-erased `AnyConfigMap`, plus `from_ini/json/xml` / `to_ini/json/xml` helpers under `HsBa::Slicer::Config`.
- **Integration surface**: `LuaAdapter.*` registers zipper, SQL adapters, Bit7z, and `ParamStore` on the Lua state; `RemoteExecutor.*` provides a PIMPL'd connection + round-robin pool for sending files to a remote service.

Dependency direction is strictly downward: LuaAdapter → archive/sql/param_store; param_store → sql_adapter; archive layers depend only on miniz/bit7z and `Utils::EventSource`. No cross-dependencies between archive, SQL, and config-map subsystems.
