Two sibling CMake subprojects (`base_static_tests`, `utils_static_tests`) are wired by the top-level `CMakeLists.txt` via `add_subdirectory`. Each subproject builds a standalone executable whose sole purpose is to include headers from the rest of the repo and trigger compile-time checks — there is no runtime harness. `base_static_tests.cpp` targets core primitives under `HsBa::Slicer::Utils`: enum name resolution (with `magic_enum::customize::enum_range` specialization), `NamedRawPtr`, `template_call`, `AllValidEnum`, `any_visit`, `tuple_each`, coroutines (`Task`, `Generator`, `CustomAllocatorTask`), and the type-info-driven `AnyObject` system (requires a `GetTypeInfo<T>` template specialization per user type). `utils_static_tests.cpp` targets higher-level utilities: JSON/XML/YAML struct serialization through `struct_json.hpp` / `struct_xml.hpp` / `struct_yaml.hpp` using the `StaticReflect::FieldInfo` + `FieldList` registration pattern, plus Lua interop via `LuaNewObject` and `LuaAnyObject`. Dependency direction is one-way: tests depend on `base/` and `utils/` headers; nothing in the production code depends back on this module.
