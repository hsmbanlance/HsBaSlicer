Built as a single static library `HsBaSlicerUtils` via `utils/CMakeLists.txt`, composed of four orthogonal sub-areas with no internal dependencies between them:
- Lua bridge: `LuaAnyObject.{hpp,cpp}` exposes `base/any_object.hpp` values to Lua through a CRTP hierarchy (`LuaAnyObjectNewCastBase` → `LuaAnyObjectNewCastAbstract` → `LuaAnyObjectNewCastImpl<T, TypeName>`) plus per-basic-type specializations (`int`, `double`, `string`, …) and a `RegisterAnyObject` entry point; `LuaDllLoader.{hpp,cpp}` wraps `boost::dll` to resolve and call exported symbols from runtime DLLs, generating `lua_dll_get_function` / `lua_dll_call_function` templates parameterized on `Ret(Args...)` signatures.
- Graph algorithms: `Graph.hpp` defines `graph::concepts` (`TSPWeight`, `DirectedGraphTag`, `UndirectedGraphTag`, `VertexIdType`) and a `BaseGraph<IdType, VertexProperty, EdgeProperty, Weight, DirectionTag, VertexDescription>` wrapper over `boost::adjacency_list`; `DirectedGraph` / `UndirectedGraph` are thin specializations. `graph::algorithm` provides BFS/DFS/Dijkstra/Bellman-Ford/A*/Prim/Kruskal/connected-components/strong-components/topological-sort/max-flow (Boykov-Kolmogorov) and a `GeneticTSP` solver. `AreaGraph.hpp` builds a two-level area/gate graph on top of this base, exposing `ExpandedGraphDump` (all entry/exit vertices + internal edges) and `PairwiseGraphDump` (N×N shortest-path cost matrix) so external consumers — notably Lua scripts — can implement custom path optimization over the full combination structure.
- Serialization: `struct_concepts.hpp` defines `Aggregte` and `Reflectable` concepts; `struct_json.hpp` / `struct_xml.hpp` / `struct_yaml.hpp` provide parallel `to_json`/`from_json`/`write_*`/`read_*` template APIs dispatching on those concepts (aggregate via Boost.PFR, reflectable via `StaticReflect::Reflector`, custom via `RapidJsonValueConvertible`).
- App config: `app_config.{hpp,cpp}` is a thread-safe singleton (`AppConfigSingletone`) exposing external tool paths (e.g. 7-Zip).
Dependency direction is one-way: this module depends on `HsBaSlicerBase`, `HsBaSlicerFileOperator`, Boost (date_time, dll, graph, pfr, container_hash), rapidjson, tinyxml2, yaml-cpp, and Lua; nothing in the rest of the repo is referenced back into here except through the public headers it exports. Precompiled headers are centralized in `pch_headers.hpp`.
