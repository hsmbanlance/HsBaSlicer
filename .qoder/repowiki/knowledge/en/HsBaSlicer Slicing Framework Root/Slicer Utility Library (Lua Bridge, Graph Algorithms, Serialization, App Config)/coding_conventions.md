- Lua-exposed types follow a CRTP registration pattern: a base interface (`LuaAnyObjectNewCastBase`) with `GetNewFuncPair`/`GetCastFuncPair`, an abstract CRTP helper (`LuaAnyObjectNewCastAbstract`), and a concrete impl (`LuaAnyObjectNewCastImpl<T, TypeName>`) that produces `new_<type>` / `cast_<type>` functions.
- Serialization backends share a uniform API surface (`to_json`/`from_json`/`write_*`/`read_*`) dispatched by C++20 concepts (`Aggregte`, `Reflectable`, `RapidJsonValueConvertible`) so callers do not branch on format.
- Template-heavy code uses `std::index_sequence` expansion helpers (e.g. `add_reflectable_members_impl`, `set_reflectable_fields_impl`) to work around MSVC template-lambda parsing limitations instead of relying on fold expressions.
- Error propagation uses the project's exception hierarchy (`RuntimeError`, `InvalidArgumentError`, `IOError`) rather than raw `throw` or error codes across both graph and serialization code.
- Graph algorithm functions are constrained with `requires` clauses on `Graph::WeightType` and `Graph::DirectionTagType` concepts (`ArithmeticWeight`, `DirectedGraphTag`, `UndirectedGraphTag`) to gate directedness and numeric-weight requirements at the call site.
