Each subdirectory under `samples/` is an independent CMake target (one per printing technology: FDM, SLA, SLM, LOM, SLS, TDP, WAAM) plus two cross-cutting samples — `Custom` (fully Lua-defined pipeline via `custom_pipeline.h`) and `LibHsBaSlicer` (direct C++ API + C++20 module). The C++ entry points (`main.cpp` in each folder) follow a uniform pattern: create a default config struct (`HsBaCreateDefaultConfig` / `HsBaCreateDefaultCustomConfig`), set model/output fields, call a synchronous or async run function (`HsBaRunFdmPipeline`, `HsBaRunCustomPipeline`, `HsBaRunCustomPipelineAsync`), then free the result with `HsBaFreePipelineResult` / `HsBaFreeCustomPipelineResult`. `samples/Custom/main.cpp` additionally ships a hand-rolled Protobuf wire encoder/decoder to exercise the `FromProtoBytes`/`ToProtoBytes` C ABI without linking `HsBaSlicerProto`. `samples/LibHsBaSlicer` demonstrates both the legacy header-based C++ API (`main_header.cpp`) and the C++20 module import path (`import hsba.slicer;` in `main_module.cpp`). All samples share the Stanford Bunny STL from `samples/FDM/models/` and copy their own `scripts/` directories into the build output via `POST_BUILD` custom commands. Dependency direction is one-way: samples link against `DllHsBaSlicer` (C ABI) or `LibHsBaSlicer`/`ModuleHsBaSlicer` (C++ API); they do not depend on each other except for sharing the STL asset.
