Each subdirectory under tests/ mirrors a production library and contains one or more `*_test.cpp` files that compile into a standalone Boost.Test executable. The single `tests/CMakeLists.txt` is the build manifest: it calls `find_package(Boost ... unit_test_framework)`, defines each test target with `add_executable`, links against the corresponding `HsBaSlicer*` / `LibHsBaSlicer` / `HsBaPaths` / `HsBaSupport` / `HsBaCipher` targets plus `Boost::unit_test_framework`, registers every binary with `enable_testing()` + `add_test()`, and aggregates them in the `ALL_TEST_TARGETS` list for a `RunAllTests` custom target driven by CTest. Conditional compilation gates (`HSBA_COPL`, `HSBA_POLYGON_DUMP`, `TARGET HsBaSlicerCADModel`, `HSBA_USE_DLL_LOADER`) select optional test binaries (CGAL, Lua polygon ops, OCCT). Tests depend only on the public headers of the modules they exercise; there are no shared test utilities — cross-cutting helpers live inside the source being tested (e.g. `Mock::MockRegistry` in `utils/LuaAnyObject.hpp`). DLL-boundary tests ship tiny companion DLLs (`mock_cad_dll.cpp`, `mock_dll_loader_dll.cpp`, `mock_point_cloud_dll.cpp`) built alongside the test to verify dynamic loading of user-provided plugins.
