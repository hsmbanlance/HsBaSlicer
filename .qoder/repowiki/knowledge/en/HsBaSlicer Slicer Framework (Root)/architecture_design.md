The root `CMakeLists.txt` is the single assembly point: it probes compiler features (concepts, ranges, coroutines, NTTP, template-template matching), toggles platform flags (`HSBA_DESKTOP`, `HSBA_MOBILE`, `HSBA_GAME_CONSOLE`), gates optional subsystems via vcpkg manifest features (`rest-api`, `copyleft`), then `add_subdirectory` in a strict dependency order — `proto` → `base` → `cipher` → `utils` → `logger` → `2D` → `paths` → `fileoperator` → `meshmodel` → `cadmodel` → `pointcloud` → `preprocess` → `support` → `pipelinetypes` → `convert` → `LibHsBaSlicer` → `ModuleHsBaSlicer` → `DllHsBaSlicer` → `HsBaSlicer` → `version`. Three public faces are produced:
- `DllHsBaSlicer` (shared library) exposing a stable C ABI per technology (FDM/SLA/SLS/SLM/LOM/TDP/WAAM/file_transfer/custom/param_store) plus `initialize`, `job_control`, `progress_stage`, `geometry_store`, `lua_register`.
- `LibHsBaSlicer` (static/shared C++ library) offering the same pipeline stages as typed C++ classes under `Slice/Preprocess/Support/Fill/Path/Floor/ParamStore/Extends`.
- `ModuleHsBaSlicer` (optional C++20 module wrapper `hsba_slicer.cppm`).
Optional `restapi/` builds an HTTP server on cpp-httplib that proxies the DllHsBaSlicer C ABI; `samples/*/main.cpp` demonstrate direct usage of each technology. The build installs targets under `<prefix>/include/HsBaSlicer/...` with a generated `HsBaSlicerConfig.cmake` / `HsBaSlicerTargets.cmake` so downstream projects use `find_package(HsBaSlicer)` and link `HsBaSlicer::DllHsBaSlicer` or `HsBaSlicer::LibHsBaSlicer`. Tests live under `tests/` (gtest-style) and `static_tests/`; coverage is gated by `HSBA_COVERAGE` and enforced at CI time (Core ≥ 45%, Other ≥ 25%).
