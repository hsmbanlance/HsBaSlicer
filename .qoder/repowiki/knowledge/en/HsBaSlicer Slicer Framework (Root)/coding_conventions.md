- Feature-gated compilation uses CMake options (`HSBA_SLICER_USE_TESTS`, `HSBA_BUILD_REST_API`, `HSBA_SLICER_MODULE`, `HSBA_HSBA_USE_BIT7Z`, `HSBA_COPL`) that propagate `HSBA_*` preprocessor defines to source code, keeping platform/kernel selection out of runtime logic.
- Each technology slice (FDM, SLA, SLS, SLM, LOM, TDP, WAAM) is implemented as a paired `.cpp`/`.h` file inside both `DllHsBaSlicer/` (C ABI) and `LibHsBaSlicer/<Technology>/` (C++ class), sharing the same naming convention for easy parallel discovery.
- Public C ABI symbols in `DllHsBaSlicer` are exported through `dllexport.h` and declared in per-pipeline headers (`fdm_pipeline.h`, `sla_pipeline.h`, …) rather than via inline macros scattered across sources.
- Lua integration follows a uniform pattern: a `LuaAdapter.{cpp,h}` (or `Lua*` pair) in each domain (`2D`, `cipher`, `fileoperator`, `support`) registers functions into a shared Lua state, while `LibHsBaSlicer/Extends/lua_pipeline.hpp` provides the higher-level pipeline binding layer.
- Cross-cutting types are defined once in `proto/*.proto` and regenerated into `convert/` bidirectional adapters (`Msg2PipelineConfig` / `PipelineConfig2Msg`, `Msg2Eigen` / `Eigen2Msg`, `Msg2FullTopoModel`), so serialization formats never duplicate business data structures.
- Platform capability detection is centralized in `cmake/feature_check.cmake` and consumed via `check_cxx_feature_*` helpers that set `HAS_*` variables and corresponding `HSBA_HAS_*` / `HSBA_NO_*` compile definitions.
