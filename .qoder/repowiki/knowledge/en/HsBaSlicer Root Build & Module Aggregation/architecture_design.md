This is the repository root — a CMake aggregator rather than a source module. It declares global compiler requirements (C++20, concepts/ranges/source_location), feature probes via `static_check/feature_check.cmake`, and platform toggles (`HSBA_DESKTOP`/`HSBA_MOBILE`/`HSBA_GAME_CONSOLE`). Dependency resolution is centralized: Boost, Clipper2, miniz, bit7z, Protobuf, RapidJSON, Eigen3, OpenSSL, OpenCV, libigl, CGAL/OpenCASCADE (gated by `HSBA_COPL`), OpenVDB, sqlpp11, Lua, tinyxml2, yaml-cpp, magic_enum are all `find_package`-ed here. Subdirectories are added in dependency order: `proto` → `base` → `cipher` → `utils` → `logger` → `2D` → `paths` → `fileoperator` → `meshmodel` → `cadmodel` → `pointcloud` → `preprocess` → `support` → `pipelinetypes` → `convert` → `LibHsBaSlicer` → `ModuleHsBaSlicer` → `DllHsBaSlicer` → `HsBaSlicer` → `version`. Optional targets gated by options: `restapi` (cpp-httplib, requires `VCPKG_MANIFEST_FEATURES=rest-api`), `samples/*` per technology (FDM/SLA/SLS/SLM/LOM/TDP/WAAM/Custom/LibHsBaSlicer), `tests`, `static_tests`, `docs` (Doxygen). Install/export is configured with `GNUInstallDirs` + `configure_package_config_file` producing `HsBaSlicerTargets.cmake` under `<prefix>/lib/cmake/HsBaSlicer/`, and copies `utils/logcfg.ini` / `restapi/restapi.ini` into the build output directory. Windows UTF-8 active code page is applied via `cmake/HsBaWindowsUtf8.cmake` so narrow-char paths handed to libigl/CGAL/OCCT/OpenVDB/miniz are interpreted as UTF-8.
