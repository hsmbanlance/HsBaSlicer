The module centers on the `ISupport` abstract interface in `ISupport.hpp`, which defines a per-layer `Generate(current_layer, prev_layer, layer_height, config)` contract plus a default `GenerateAll` that iterates layers with shared-column downward growth. Concrete strategies live as sibling classes: `FdmPlaneSupport`, `FdmTreeSupport`, `FdmHoneycombSupport` (in `FdmSupport.*`), `SlaSacrificialSupport` (in `SlaSupport.*`), and `LuaSupport` (in `LuaSupport.*`) — all derived from `ISupport`. Overhang detection is decoupled into the stateless `OverhangDetector` static utility (`OverhangDetector.*`), used by both the base `ISupport::GenerateAll` loop and generators that need raw overhang data. Configuration is centralized in `SupportConfig.hpp` via a base `SupportConfig` struct extended by `FdmSupportConfig` and `SlaSupportConfig`. The Lua path is split into `LuaSupport` (script loader/executor) and `LuaAdapter` (exposes 2D polygon helpers to Lua). Dependency direction inside the module is one-way: concrete generators depend on `ISupport` + `SupportConfig` + `OverhangDetector`; only `LuaSupport` additionally depends on the external Lua runtime via `target_include_directories(HsBaSupport PRIVATE ${LUA_INCLUDE_DIR})`. The CMake target `HsBaSupport` is a STATIC library linking `HsBaSlicerBase`, `HsBaSlicer2D`, `HsBaSlicerUtils`, Clipper2 and `${LUA_LIBRARIES}`.
