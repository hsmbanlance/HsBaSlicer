Single-process server built on cpp-httplib (`main.cpp` parses CLI + `restapi.ini`, then calls `RunServer`). Internal layering inside `routes.cpp`:
- Entry / bootstrap: `RunServer` constructs `UploadStore`, `JobManager`, a `Ctx` holding config/jobs/uploads/start time, installs an `AuthGate` pre-routing hook, registers all routes, and blocks on `listen()`.
- Route handlers: thin functions per endpoint (health, version, pipelines, default-config, submit, status, result, geometry/path/layer, package/list/entry, cancel, params save/load, uploads list/status/delete) that translate between httplib Request/Response and the C ABI of `DllHsBaSlicer`.
- Domain services: `job_manager.{hpp,cpp}` owns the in-process worker pool (`std::thread` deque), lifecycle states (Queued/Running/Success/Failed/Cancelled), cooperative cancellation via `std::atomic<bool>` injected into configs, and TTL-based reaping; `pipeline_executor.{hpp,cpp}` bridges to `DllHsBaSlicer::ExecutePipeline`; `upload_store.{hpp,cpp}` persists multipart files under `upload_dir/<job-id>/` and evicts by TTL/count/size/manual; `config_bridge.{hpp,cpp}` deserializes/serializes pipeline configs across JSON/XML/proto and binds uploaded model paths back into reflected fields; `package_reader.{hpp,cpp}` reads finished archive results per request without keeping state.
- Dependency direction: restapi → DllHsBaSlicer (C ABI via `geometry_export.h`, `initialize.h`, `param_store_pipeline.h`, `version_info.h`) + fileoperator(ParamStore) + utils(struct_json/struct_xml/struct_yaml) + pipelinetypes(pipeline_types.h). Samples/Lua callers never depend on restapi — they call DllHsBaSlicer directly.
- Auth is enforced uniformly through `svr.set_pre_routing_handler` checking `Authorization: Bearer` or `X-API-Key` against `restapi.ini [auth]`, with loopback bypass and optional TLS requirement. Uploads are opt-in via `[upload] dir` and gated behind `ctx.uploads.Enabled()`.
