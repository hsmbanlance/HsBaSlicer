- Every route handler follows the same shape: compute `DataFormat fmt = TargetFormat(req, ctx.cfg)`, build a plain aggregate view struct, and emit it via `ReplyValue(res, status, view, fmt, "Root")` so JSON/XML rendering is uniform.
- Errors are emitted through `ReplyError(res, status, message, detail, fmt)` wrapping an `ErrorView{status, message, detail}`, giving clients a consistent error envelope regardless of endpoint.
- Multipart parts are accessed uniformly via the local `FindPart(req, name)` helper that abstracts over cpp-httplib's `Request::files` vs `Request::form.files/fields` split, returning `std::optional<MultipartPart>`.
- Optional query parameters use `ParseSizeParam` (strtoul-based) or `req.get_param_value("...") == "1" || ... == "true"` rather than ad-hoc parsing, keeping boolean/size semantics consistent across endpoints.
- All public reply structs (`HealthView`, `KindList`, `JobStatusView`, `GeometrySummaryView`, `LayerGeometryView`, `GeometryPathView`, `PackageListingView`, `CancelView`, `Index`) are declared at named namespace scope so MSVC's `boost::pfr` can reflect them (anonymous-namespace types trigger C7631).
- Configuration values flow from `restapi.ini` into a single `ServerConfig` struct with built-in defaults; optional features (TLS, auth, uploads, paramstore) are enabled only when their corresponding fields are non-empty/non-zero.
