The module centers on a single abstract base `IPath` (`IPath.hpp`) declaring a uniform `Save(path)` / `ToString()` API family overloads that accept either native serialization or an inline Lua script (with optional named entry function and a `lua_State*` registration callback). Concrete classes form two parallel hierarchies:
- Point-based: `PointsPath` holds an ordered `std::vector<GPoint>` of G-code motion commands and emits raw G-code text.
- Layer-based: `LayersPath` stores per-layer `(config string, PolygonsD)` pairs; `GCodePath` extends it to generate firmware-specific G-code (Marlin/RepRap/Klipper) with spiralized continuous walls and embedded Base64 thumbnails; `RobotPath` and `WeldRobotPath` extend it for robotic/welding outputs; `ImagesPath` serializes raster previews.

Dependency direction is strictly downward: `GCodePath` → `LayersPath` → `IPath`; `RobotPath`/`WeldRobotPath` → `LayersPath` → `IPath`; `ImagesPath`/`PointsPath` → `IPath`. The only external C++ dependencies are `HsBaSlicerBase`, `HsBaSlicerFileOperator`, `HsBaCipher`, `HsBaSlicer2D`, `HsBaSlicerUtils`, plus the Lua interpreter (included via `${LUA_INCLUDE_DIR}` and linked as `${LUA_LIBRARIES}`). Lua headers are forward-declared in the public `IPath.hpp` so callers never include `lua.hpp` directly.
