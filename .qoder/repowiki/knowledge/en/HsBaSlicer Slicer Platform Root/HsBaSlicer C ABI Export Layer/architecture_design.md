The module is built as a SHARED library on desktop platforms and as a STATIC archive on iOS (per `CMakeLists.txt`), with every public symbol annotated via the `HSBA_SLICER_API` macro from `dllexport.h`. It links against `LibHsBaSlicer` plus all supporting libraries (`HsBaSlicerBase`, `HsBaSlicerUtils`, `HsBaSlicerMesh`, `HsBaSlicer2D`, `HsBaPreprocess`, `HsBaSupport`, `HsBaPaths`, `HsBaSlicerFileOperator`, `HsBaVersion`, `HsBaSlicerConverter`, `HsBaSlicerProto`) — code-level constraint enforced by comment: this layer only calls exported functions of `LibHsBaSlicer`, never reaches into its internals. Per-printer technology (FDM, SLA, SLS, SLM, LOM, TDP, WAAM) there is a thin `*_pipeline.{h,cpp}` pair that translates between protobuf wire format and C structs; these share cross-cutting helpers in `model_preprocess`, `pipeline_convert`, `pipeline_parallel`, `file_transfer_pipeline`, `param_store_pipeline`, `lua_register`, `event_source_register`, and `initialize`. The two child modules split responsibilities: `dll_bootstrap` owns the one-time bootstrap (`initialize`, event-source registration, version info) while `fdm_slicing_engine` owns the FDM-specific proto serialization; other printer pipelines reuse the same C ABI pattern without duplicating bootstrap logic.
