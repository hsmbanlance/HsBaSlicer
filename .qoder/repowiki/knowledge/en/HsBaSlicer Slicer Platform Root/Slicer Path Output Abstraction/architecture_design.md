The module is a static CMake library `HsBaPaths` built from six concrete path types layered on a single abstract interface:
- `IPath.hpp` defines the core contract (`Save`/`ToString` overloads accepting native file paths, inline Lua scripts, script files with named entry functions, plus a `lua_reg` callback to expose extra Lua bindings). It also declares the shared `OutPoints3` struct.
- `LayersPath` implements `IPath` around an ordered vector of per-layer `(config string, PolygonsD)` pairs; it is the base for `GCodePath`, which adds firmware-specific G-code emission (Marlin/RepRap/Klipper) and continuous spiral-wall support via `PathPoint3D`.
- `RobotPath` implements `IPath` around a vector of `RLPoint` moves and emits brand-specific robot language (ABB/KUKA/FANUC) through private `GenerateAbbCode`/`GenerateKukaCode`/`GenerateFanucCode` helpers. `WeldRobotPath` derives from `RobotPath`, replacing the point buffer with `WeldRLPoint` (base `RLPoint` + `WeldParam`) and adding arc start/end logic per brand.
- `PointsPath` and `ImagesPath` are sibling leaf implementations of `IPath` for raw point clouds and image data respectively.
Dependency direction is strictly downward: `WeldRobotPath → RobotPath → IPath`; `GCodePath → LayersPath → IPath`; all other classes depend only on `IPath`. Lua integration is declared via forward-declared `struct lua_State` in headers and linked through `${LUA_LIBRARIES}` / `${LUA_INCLUDE_DIR}`.
