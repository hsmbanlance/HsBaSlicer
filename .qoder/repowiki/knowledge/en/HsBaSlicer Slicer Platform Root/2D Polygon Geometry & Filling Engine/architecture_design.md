Built as a single static CMake library `HsBaSlicer2D` (`2D/CMakeLists.txt`) with a clear internal layering:
- Primitive layer: `IntPolygon.{hpp,cpp}` defines integer-coordinate polygons used by Clipper2; `FloatPolygons.{hpp,cpp}` provides double-precision aliases (`Point2D`, `PolygonD`, `PolygonsD`) over `Clipper2Lib::PointD/PathD/PathsD` plus boolean ops (Union/Intersection/Difference/Xor), area, simplification, shape constructors (rectangle/circle/ellipse/regular polygon), text-to-polygons via FreeType, and int↔double conversion.
- Fill layer: `PolygonFill.{hpp,cpp}` exposes fill algorithms (`OffsetFill`, `LineFill`, `SimpleZigzagFill`, `ZigzagFill`, `CompositeOffsetFill`, `HybridFill`) operating on integer `Polygons`; an enum `FillMode` selects the interior pattern. Custom fills are loaded from Lua scripts via `LuaCustomFill` / `LuaCustomFillString`.
- Image I/O layer: `ImageToPolygons.{hpp,cpp}` converts between PNG/JPEG bitmaps and polygons through thresholding (`FromImage`, `FromImageMulti`) and renders polygons back to images (`ToImage`, `ToImageBuffer`, `LuaToImage`).
- Lua bridge: `LuaAdapter.{hpp,cpp}` registers all polygon operations into a `lua_State` and provides push/table-conversion helpers for both integer and double polygon types; `PolygonFill` and `ImageToPolygons` forward-declare `lua_State` to avoid including `<lua.hpp>` in their headers.
Dependency direction is strictly one-way: `ImageToPolygons` → `FloatPolygons` → `IntPolygon`; `PolygonFill` → `FloatPolygons` + `IntPolygon`; `LuaAdapter` depends on both polygon layers. External dependencies (Clipper2, libpng, libjpeg-turbo, Lua, optional OpenCV/Freetype) are wired in `CMakeLists.txt` with platform guards for iOS/game-console builds.
