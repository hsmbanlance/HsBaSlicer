Three sibling sub-packages each implement the shared `base/IModel` interface with a distinct geometric kernel:
- `cadmodel/` — OCCT-based `OcctModel` wrapping a `TopoDS_Shape`, exposing STEP/IGES/VRML/BRep load/save, boolean ops (`Union`/`Intersection`/`Difference`/`Xor`), thick-solid, primitives (`CreateBox`/`Sphere`/`Cylinder`/`Cone`/`Torus`) and extrusion via `CreatePrime`. `UserCustomCADModel` is an `IModel` adapter that dynamically loads a user DLL/SO through `IUserCustomCAD` + `UserCustomCADDll` to delegate CAD operations.
- `meshmodel/` — two mesh kernels: `IglModel` (libigl-backed Eigen matrices) and `CgalModel` (CGAL-backed); both implement `IModel` with STL/OBJ/PLY/OFF I/O, normals, booleans and primitives. `FullTopoModel` is not an `IModel`; it consumes any `IModel` in its constructor to rebuild a full vertex/edge/face topological graph and offers `Slice`/`UnSafeSlice`/`SliceFast` plus Lua-driven `SliceLua` scripting over V/E/F globals.
- `pointcloud/` — `OpenVdbModel` stores points in an OpenVDB `Vec3fGrid` and adds KNN/radius search, voxelization, downsampling, statistical outlier removal, normal estimation and level-set mesh reconstruction; `UserCustomPointCloudModel` mirrors this API against a user plugin via `IUserCustomPointCloud` + `UserCustomPointCloudDll`.

Dependency direction is one-way: these backends depend on `base/IModel` and 2D polygon types (`FloatPolygons.hpp`, `IntPolygon.hpp`), but are never depended on by them. Each sub-package ships its own `CMakeLists.txt` so they can be built independently. The `HSBA_NO_DLL_LOADER` preprocessor gate isolates the user-plugin loader code from builds that omit dynamic loading.
