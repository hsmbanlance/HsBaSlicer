Single-file C++20 module (`hsba_slicer.cppm`) built as a STATIC library via CMake. The module is split into two logical halves: the exported interface (declarations + inline definitions under `export module hsba.slicer;` in namespace `HsBa::Slicer`) and the implementation body after the closing namespace brace, which calls into LibHsBaSlicer free functions (`Slice`, `GenerateAllFdmSupport`, `FillWithBorder`, `GenerateGCodePathV2`, `SaveSlsPackageLua`, …). A separate `module_anchor.cpp` provides an empty translation unit so CMake's archiver produces `ModuleHsBaSlicer.lib`. Dependency direction is one-way: this wrapper depends on `LibHsBaSlicer`, `HsBaPipelineTypes`, Eigen3, Clipper2, and Lua; consumers import `hsba.slicer` and link against the static archive. The public surface groups into: (1) `Model` RAII handle over `IModel`; (2) per-process pipeline classes (`FdmPipeline`, `SlaPipeline`, `SlsPipeline`, `SlmPipeline`, `LomPipeline`, `TdpPipeline`, `WaamPipeline`, `FileTransferPipeline`, `ParamStorePipeline`, `CustomLuaPipeline`); (3) Lua extension entry points (`add2DFunction`, `add3DFunction`, `addFileFunction`, `addEventCallback`, `addZipperEventCallback`, `addDBEventCallback`); (4) utility converters (`toDouble`, `toInt`, `versionJson`, `versionXml`). Config structs from `pipelinetypes/pipeline_types.h` are re-exported as type aliases so callers configure pipelines with plain C structs while the wrapper owns lifecycle.
