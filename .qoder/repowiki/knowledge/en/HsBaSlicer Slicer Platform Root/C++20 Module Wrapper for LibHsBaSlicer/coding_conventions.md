- Each pipeline variant (FDM, SLA, SLS, SLM, LOM, TDP, WAAM, FileTransfer, ParamStore, CustomLua) is exposed as a dedicated class holding a single config struct member and exposing a `run(const Model&)` method that throws `SlicerError` on failure.
- Lua-driven stages (support, fill, floor, export) are selected at runtime by checking a `*_lua_script` field in the config and falling back to the native algorithm when absent, with a default function name like `generate_support` / `export_sls` used when `*_lua_func` is unset.
- Layer iteration follows a uniform pattern: compute layer count from model bbox height divided by `cfg_.layer_height`, loop `i` from 0..layers-1, use `cfg_.first_layer_height` for i==0 and `first_layer_height + i * layer_height` otherwise, and convert integer slices to double via `UnIntegerization` before passing to support/fill routines.
- Public types from `pipelinetypes/pipeline_types.h` and `Support` namespace are re-exported as `using` aliases inside `HsBa::Slicer` so consumers see them without including the underlying headers.
- The module uses a global module fragment (`module;`) for non-exported includes (Windows headers, std, third-party) and declares the exported interface only after `export module hsba.slicer;`, keeping declarations and implementations in one compilation unit to avoid MSVC C2572 implicit-import errors.
