Two complementary artifacts under one scope:
- `pipelinetypes/pipeline_types.h` is a standalone, header-only INTERFACE library (`HsBaPipelineTypes`, see `CMakeLists.txt`) that exposes `extern "C"` typedefs — enums (`HsBaFillMode_t`, `HsBaSupportPattern_t`, `HsBaGCodeFirmware_t`, …), per-pipeline config/result structs (`HsBa*PipelineConfig_t` / `HsBa*PipelineResult_t`), progress/result callback function pointers, and inline `HsBa*ConfigDefault()` initializers. It deliberately omits `HSBA_SLICER_API`/`dllexport.h` so downstream consumers (e.g. `convert`) can include it without linking `DllHsBaSlicer`. A final `HsBaPipelineKind` enum mirrors `fileoperator/param_reflect.hpp::PipelineConfigTag` to tie configs to the parameter store.
- `types/hsba_pipeline.d.lua` is an EmmyLua `.d.lua` declaration file referenced by `.luarc.json`; it documents the runtime `HsBa` global table, built-in stage environments (`generate_support`, `generate_fill`, `generate_floor`, `export_sls/slm/lom/tdp/waam/sla`, `run_pipeline`), shared libraries (`PolygonOperations`, `Zipper`, `Cipher`, `SQLiteAdapter`, …), and per-process step summaries used by sumneko-lua/LuaLS for autocomplete in `samples/` scripts.
Dependency direction: this module is a leaf — it has no runtime dependencies on the rest of the slicer; the C ABI is defined here and implemented elsewhere, while the Lua declarations mirror the same runtime surface exposed by the C++ side.
