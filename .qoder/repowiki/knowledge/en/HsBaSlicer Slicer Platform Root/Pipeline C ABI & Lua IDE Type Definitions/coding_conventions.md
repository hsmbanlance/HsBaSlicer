- Each pipeline (FDM/SLA/SLS/SLM/LOM/TDP/WAAM/FileTransfer/Custom) follows a fixed triplet: a `HsBa*PipelineConfig_t` struct, a matching `HsBa*PipelineResult_t` struct, paired `HsBa*ProgressCallback` / `HsBa*ResultCallback` function-pointer typedefs, and an inline `HsBa*ConfigDefault()` initializer that zero-initializes string fields and sets numeric defaults.
- All public symbols use the `HsBa*` namespace prefix (structs, enums, callbacks, default functions) and are wrapped in `extern "C"` blocks so they form a stable C ABI independent of C++ name mangling.
- Result structs consistently expose `success` (int), `total_layers` (int), a UTF-8 `char*` output field (`gcode_content` / `export_path` / `output_path`), an `error_message` char*, and `elapsed_seconds`, with comments directing callers to the corresponding `HsBaFree*PipelineResult` free function.
- Optional Lua customization hooks are expressed as paired `*_lua_script` / `*_lua_func` const-char fields on each config struct, allowing a user script path plus a default function name (e.g. `generate_support`, `export_sls`).
- EmmyLua declarations in `hsba_pipeline.d.lua` group types by pipeline process (FdmPreprocess/FdmSlice/FdmSupportStage/… and parallel Sla*/Sls*/Slm*/Lom*/Tdp*/Waam* groups) using `@class` aliases, mirroring the step ordering documented in the file header comment.
