Built as a single static library `HsBaSlicerUtils` via `utils/CMakeLists.txt`, grouping orthogonal utilities into four cohesive sub-areas with no internal sub-packages:
- Lua bridge: `LuaAnyObject.{hpp,cpp}` exposes `base::AnyObject` to Lua through a CRTP hierarchy (`LuaAnyObjectNewCastBase` → `LuaAnyObjectNewCastAbstract` → `LuaAnyObjectNewCastImpl<T, TypeName>`) plus per-basic-type specializations; `LuaNewObject.hpp` provides the underlying `NewLuaObject` wrapper. `LuaDllLoader.{hpp,cpp}` wraps `boost::dll` to dynamically resolve and call exported functions from external DLLs, exposing `get_<name>` / `call_<name>` Lua bindings parameterized by `Ret(Args...)` signatures via `LuaDllGetFunction<TName, Ret, Args...>`.
- Struct serialization: `struct_concepts.hpp` defines `Aggregte`/`Reflectable` concepts; `struct_json.hpp`, `struct_xml.hpp`, `struct_yaml.hpp` provide parallel `to_json`/`from_json`/`write_*`/`read_*` templates dispatching on those concepts (aggregate via Boost.PFR, reflectable via `StaticReflect::Reflector`, custom via `RapidJsonValueConvertible`).
- Graph algorithms: `Graph.hpp` is header-only, wrapping `boost::adjacency_list` in `BaseGraph<IdType, VertexProperty, EdgeProperty, Weight, DirectionTag, VertexDescription>` and exposing shortest-path, MST, max-flow, connectivity, topological sort, and genetic TSP algorithms under `HsBa::Slicer::graph`.
- App config: `app_config.{hpp,cpp}` implements a thread-safe singleton `AppConfigSingletone` guarding shared settings (e.g. 7-Zip path) with `std::shared_mutex`.

Dependency direction is inward-only: this module depends on `HsBaSlicerBase`, `HsBaSlicerFileOperator`, Boost.Date_Time, RapidJSON, tinyxml2, yaml-cpp, and Lua; nothing inside the module depends on higher-level slicer components.
