- Lua-exposed native types are registered through the CRTP adapter chain `LuaAnyObjectNewCastBase` → `LuaAnyObjectNewCastAbstract` → `LuaAnyObjectNewCastImpl<T, TypeName>`, with one specialization per basic type (int, longlong, size_t, float, double, bool, string, cstring).
- Struct serialization overloads are dispatched by C++20 concepts (`Aggregte`, `Reflectable`, `RapidJsonValueConvertible`) using paired `add_member` / `set_field_from_json` helper templates that throw `RuntimeError` for unsupported field types.
- Public serialization APIs come in symmetric pairs: `to_json`/`from_json`, `write_json`/`read_json`, `write_pretty_json`/`read_json_from_file`, each overloaded for both `rapidjson::Value` and `rapidjson::Document`.
- DLL function registration follows a template-driven pattern: callers instantiate `detail::LuaDllGetFunction<TName, Ret, Args...>` to produce a `DllGetFunctionAbstract` whose `GetLuaDllGetFuction` / `GetLuaDllCallFuction` return the generated `lua_dll_get_function` / `lua_dll_call_function` entry points.
- Cross-cutting headers are precompiled via `target_precompile_headers(HsBaSlicerUtils PRIVATE pch_headers.hpp)` rather than being included individually by consumers.
