The module is a single static CMake library `HsBaSlicer2D` (see `CMakeLists.txt`) organized into four orthogonal layers under the `HsBa::Slicer` namespace:

- Primitive layer (`IntPolygon.hpp/.cpp`, `FloatPolygons.hpp/.cpp`): defines `Point2/Polygon/Polygons` (64-bit int) and `Point2D/PolygonD/PolygonsD` (double) as aliases over `Clipper2Lib::*`. All boolean ops (`Union`, `Intersection`, `Difference`, `Xor`), `Offset`, `Area`, `MakeSimple`, shape constructors (`MakeRectangle`, `MakeCircle`, `MakeEllipse`, `MakeRegularPolygon`), and `Integerization`/`UnIntegerization` live here. The double layer depends on the int layer for coordinate conversion; the int layer has no internal dependency.
- Fill layer (`PolygonFill.hpp/.cpp`): consumes `Polygons` from the primitive layer to generate infill patterns — offset fill, line fill, zigzag fills, composite/hybrid fills, seam randomization (`RandomizeStartPoints`), and Lua-driven custom fills. Uses `HSBA_PRE(Contracts::is_positive(...))` preconditions.
- IO layer (`ImageToPolygons.hpp/.cpp`): raster↔polygon conversion via PNG/JPEG/OpenCV/Freetype, exposing `FromImage`, `FromImageMulti`, `ToImage`, `ToImageBuffer`, plus Lua-driven variants.
- Binding layer (`LuaAdapter.hpp/.cpp`): bidirectional converters between Lua tables and both int/double polygon types, plus `RegisterLuaPolygonOperations` / `RegisterLuaPolygonFillFunctions` entry points that expose the geometry and fill APIs to Lua scripts.

Dependency direction is strictly one-way: LuaAdapter → FloatPolygons + IntPolygon → PolygonFill → ImageToPolygons. External dependencies are declared in `CMakeLists.txt`: Clipper2 (boolean/offset), libpng/libjpeg-turbo (image I/O), OpenCV (optional, gated by non-IOS/non-game-console), Lua (always), Freetype (optional, gated by `HSBA_HAVE_FREETYPE`). Debug SVG dumping is gated by the `HSBA_POLYGON_DUMP` compile definition.
