- Each pipeline exposes a pair of C ABI headers (`*_pipeline.h`) declaring `extern "C"` functions for default-config creation, synchronous run, asynchronous run, and result freeing, while the coroutine implementation lives in a sibling `.cpp` file.
- Per-pipeline internal state is split into an `InternalConfig` struct (copied from the C ABI config) and an `InternalResult` struct (converted back to the C ABI result), with `BuildConfig`/`ToCResult` helpers handling ownership of malloc'd C strings via an RAII `OwnedCString` guard.
- Layer-parallel work is expressed through `ParallelForLayers` / `ParallelForLayersAsync` from `base/parallel.hpp`, with each worker writing only to its own indexed slot in a pre-sized output vector — no shared mutable state between layers.
- The process-wide thread pool is accessed exclusively via `PipelinePool()` (lazy static singleton); callers never construct their own `ThreadPool` directly inside pipeline code.
- Lua-driven stages serialize themselves: when a Lua infill/support script is present the loop falls back to a plain `for` over layers rather than going through `ParallelForLayers`, because the Lua interpreter state is not thread-safe.
- Progress reporting goes through a local `ReportProgress(cfg, percent, stage)` helper that forwards to the caller-supplied `HsBaProgressCallback`, keeping all progress callbacks off worker threads.
