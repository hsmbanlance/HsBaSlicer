The root `CMakeLists.txt` is the single wiring point: it enforces C++20 / C11 standards, runs static feature checks (concepts, ranges, source_location, NTTP), detects desktop vs mobile vs game-console via `VCPKG_TARGET_TRIPLET`, then adds subdirectories in a strict dependency order (`proto` → `base` → `cipher` → `utils` → `logger` → `2D` → `paths` → `fileoperator` → `meshmodel` → `cadmodel`/`pointcloud` → `preprocess` → `support` → `pipelinetypes` → `convert` → `LibHsBaSlicer` → `ModuleHsBaSlicer` → `DllHsBaSlicer` → `HsBaSlicer`). Cross-cutting concerns are centralized here:
- Feature flags (`HSBA_BUILD_REST_API`, `HSBA_SLICER_MODULE`, `HSBA_COPL`, `HSBA_USE_DLL_LOADER`, `HSBA_HSBA_USE_BIT7Z`, `HSBA_SLICER_USE_TESTS`) gate entire subprojects.
- The copyleft kernel toggle (`HSBA_COPL=AUTO|ON|OFF`) switches between MIT and GPL-3.0-or-later licensing and enables CGAL/OpenCASCADE.
- Windows UTF-8 active code page manifest is applied uniformly to all executables via `cmake/HsBaWindowsUtf8.cmake`.
- Output layout is unified under `${CMAKE_BINARY_DIR}/bin/$<CONFIG>`; `restapi.ini` is copied alongside the executable when REST is enabled.
- Install/export targets (`HsBaSlicerTargets`, `HsBaSlicerConfig.cmake`) publish the public headers of `DllHsBaSlicer`, `LibHsBaSlicer`, `fileoperator`, `base`, `version`, `logger`, `convert`, `proto` generated files, and the optional REST server.
The restapi child is an optional sibling built only when `HSBA_BUILD_REST_API=ON` AND the vcpkg `rest-api` feature (cpp-httplib) is present; it depends on `DllHsBaSlicer`'s C ABI rather than on any internal C++ library, keeping the HTTP layer decoupled from the slicing engine.
