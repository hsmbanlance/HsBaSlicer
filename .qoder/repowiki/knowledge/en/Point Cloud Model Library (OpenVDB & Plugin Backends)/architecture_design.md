Two interchangeable `IModel` backends live side-by-side:
- `OpenVdbModel` (OpenVdbModel.hpp/.cpp + split impl in `OpenVdbModel_mesh.cpp`, `OpenVdbModel_analysis.cpp`, internal header `OpenVdbModel_internal.h`) stores points in an `openvdb::Vec3fGrid` and adds point-cloud operations: insertion, KNN/radius search, voxelization, downsampling, statistical outlier removal, normal estimation, centroid, merge, and level-set mesh reconstruction via OpenVDB.
- `UserCustomPointCloudModel` / `UserCustomPointCloudDll` (`UserCustomPointCloudModel.hpp/.cpp`) implement the same API surface but delegate every operation to function pointers resolved from a dynamically loaded shared library (DLL/SO) through the `IUserCustomPointCloud` ABI, which exposes C entry points typed against `HsBaVector3f_t`.

Dependency direction is one-way: both backends depend on `base/IModel.hpp` and `HsBaSlicerBase`; the plugin path additionally depends on Boost.DLL. The public headers expose only the stable `IModel` contract plus point-cloud-specific helpers; implementation details are split across `.cpp` files so that heavy template instantiations (e.g. OpenVDB meshing) stay isolated. Build-time toggles: OpenVDB linkage is optional (`if(OpenVDB_FOUND)`), and the entire plugin subsystem is gated by `#ifndef HSBA_NO_DLL_LOADER`.
