Flat collection of `.proto` files under `proto/`, all declaring `package HsbaProto;`. Primitive geometry (`point.proto`, `vector.proto`) is imported by higher-level schemas (`mesh.proto`, `path.proto`). Pipeline-specific configuration messages live in one file per technology (`fdm_pipeline.proto`, `sla_pipeline.proto`, `sls_pipeline.proto`, `slm_pipeline.proto`, `tdp_pipeline.proto`, `waam_pipeline.proto`, `lom_pipeline.proto`, `file_transfer_pipeline.proto`, `custom_pipeline.proto`), each pairing a `msg_*_pipeline_config` message with a `msg_*_pipe_result` result envelope. Shared cross-cutting concepts are split into `base_config.proto`, `transform.proto`, and `slice_config.proto`. The build layer (`CMakeLists.txt`) compiles these into a native static library `HsBaSlicerProto` via `PROTOBUF_GENERATE_CPP`, and additionally generates C#, Java, Python, and PHP bindings into `HSBA_PROTO_OUT_DIRECTORY` through custom protoc commands gated by `HSBA_PROTO_OUT_*` options. Consumers depend only on the generated headers/sources — no runtime logic lives in this module.
