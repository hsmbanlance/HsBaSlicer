- Serialization entry points come in paired `to_json`/`from_json` families plus stream/file/string variants (`write_json`, `read_json_from_file`, `read_json_from_string`, `write_pretty_json`), all templated on the target type and delegating to internal `*_impl` helpers.
- Type dispatch over heterogeneous field types is done through C++20 concepts (`Aggregte`, `Reflectable`, `RapidJsonValueConvertible`, `OptionalLike`, `ArithmeticWeight`, `DirectedGraphTag`, `UndirectedGraphTag`) combined with constrained `add_member` / `set_field_from_json` overloads rather than runtime polymorphism.
- Lua binding adapters follow a fixed CRTP pattern: a base interface (`LuaAnyObjectNewCastBase` / `DllGetFunctionAbstract`) declares virtual `GetNewFuncPair`/`GetCastFuncPair` or `GetLuaDllGetFuction`/`GetLuaDllCallFuction`, an abstract CRTP helper implements common name generation, and concrete specializations specialize for each native type or function signature.
- Errors thrown from serialization and graph operations use the project's `RuntimeError` / `InvalidArgumentError` / `IOError` exception types from `base/error.hpp` instead of raw `std::exception`.
- Public headers are guarded by `#pragma once` plus an include guard macro following the `HSBA_SLICER_<FILE>_HPP` naming scheme, and the whole library is compiled with a single precompiled header (`pch_headers.hpp`).
- External dependencies are declared exclusively in `utils/CMakeLists.txt` via `target_link_libraries(HsBaSlicerUtils PUBLIC ...)` so consumers inherit the same link requirements.
